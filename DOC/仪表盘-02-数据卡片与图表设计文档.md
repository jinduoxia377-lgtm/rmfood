## 2. 统计卡片（StatsCards）

### 2.1 设计

- 单组件承载 4 种统计卡，通过 `statIndex`（0-3）区分：
  - `0 → 配方总数`（FlaskConical / primary）
  - `1 → 实验总数`（TestTubes / secondary）
  - `2 → 进行中实验`（TrendingUp / info）
  - `3 → 已完成实验`（CheckCircle2 / success）
- 文案由 `DASHBOARD_CONFIG.statCardLabels`（app.config.ts）提供，避免硬编码。
- 数值映射在 `DashboardPage.renderCard` 中完成（`statIndexMap`）：
  - 0: `stats.formulas.total`
  - 1: `stats.experiments.total`
  - 2: `stats.experiments.by_status['in_progress']`
  - 3: `stats.experiments.by_status['completed']`

⚠️ **接口契约问题（P0-01）**：`StatsCards` 实际接受 `statIndex` prop，但 `renderCard` 通过 `CARD_COMPONENTS` 统一展开 `{card, data, ...}`，`statIndex` 未注入 → 运行时 `stat` 为 `undefined`、`label` 为空字符串。**修复方案**：在 `renderCard` 中按 `statIndexMap` 显式传入 `props.statIndex = idx`（源码当前仅计算 total/loading/error，遗漏 statIndex 传参）。

### 2.2 StatCard UI 基元

`StatCard`（@/components/ui）= Card 包裹 + 顶部 accent bar + 图标容器 + 标签 + 大字号数值，4 种 variant（primary/secondary/info/success）对应主题色。

## 3. 图表卡片（Recharts 配置规范）

### 3.1 研发趋势（TrendChart，AreaChart）

- **数据映射**：后端 `{date, formulas_created, experiments_created, formulas_approved}` → 前端 `{date: 'M月D日 周X', 新增配方, 新增实验, 批准配方}`。
- **视觉规范**：
  - 容器高 200px，`ResponsiveContainer`
  - 渐变填充：`url(#colorFormula)`（success 色 0.25→0）、`url(#colorExp)`（accent 色 #8B5CF6）
  - 批准配方：虚线（`strokeDasharray="5 5"`，无填充）
  - 网格：`strokeDasharray="3 3"` + CSS 变量 `var(--border-color)`，`opacity 0.3`
  - 坐标轴：`fontSize 11`、`var(--text-muted)`、无轴线
- **Tooltip 规范**（CHART_CONFIG.tooltip 基准）：`var(--card-bg-solid)` 背景、`--border-color` 描边、圆角 8、阴影、`padding 10px 14px`。
- **空态**：`EmptyState`（BarChart3 图标 28px +「暂无趋势数据」+ 新建配方 CTA → `/formulas/new`）。

### 3.2 配方状态分布（FormulaPieChart）

- 数据来源：`stats.formulas.by_status` → 过滤 `value > 0` → `[{name: STATUS_LABELS[status], value, key}]`。
- Donut 规范（CHART_CONFIG.pie）：`innerRadius 50 / outerRadius 80 / paddingAngle 3`；Cell 取 `STATUS_CONFIG.colors[status]`。

### 3.3 实验状态统计（ExperimentBarChart）

- 数据来源：`stats.experiments.by_status`（同上过滤）。
- Bar 规范（CHART_CONFIG.bar）：`barSize 28 / borderRadius [0,6,6,0]`。

### 3.4 主题变量依赖

全部图表取色依赖 CSS 变量：`--card-bg-solid`、`--border-color`、`--text-muted`、`--color-success`、`--color-accent`、`--color-primary`、`--color-secondary`。暗色模式通过变量重映射自动适配（无需 dark: 类），是图表卡片**不出现暗色硬编码色值**的关键。

## 4. 列表卡片

### 4.1 行结构规范

| 元素 | 规范 |
|---|---|
| 行 | `px-6 py-3` + hover 背景（`bg-neutral-50 dark:bg-neutral-800/40`）+ 整行 Link |
| 主信息 | `text-xs font-semibold` 标题（truncate）+ `text-xs` 副信息（编码/创建人） |
| 状态 | `StatusBadge`（右侧，shrink-0） |
| 分隔 | 列表容器 `p-0`，行间 `divide-y divide-neutral-100 dark:divide-neutral-800/40` |
| 空态 | `px-6 py-10 text-center`「暂无…」 |
| 截断 | 配方/实验/审核队列取前 5/5/6 条，动态取前 8 条 |

### 4.2 待办优先级（TodosList）

- `high → bg-warning-500`、`medium → bg-secondary-500`、`low → bg-neutral-300`（2×2 圆点）
- 路由：`type==='review_formula' → /formulas/:id`，其余 `→ /experiments/:id`
- 角标：Badge neutral 显示总数

### 4.3 审核队列（ReviewQueueList）

- 行内展示功效标签 `target_effects.slice(0,3)`（primary 小 Badge 换行）
- 路由：`/formulas/:id`

### 4.4 动态时间线（ActivityTimeline）

- 类型图标：`formula → FlaskConical`（primary 底）、`experiment → TestTubes`（secondary 底）；category/term 走默认
- 每行：类型图标 + `event` 文本 + 标题 + `StatusBadge` + 相对时间
- 截断前 8 条

## 5. 快捷操作（QuickActions）

### 5.1 功能

5 个默认入口（localStorage `rmfood_quick_actions` 覆盖）：

| 入口 | 路由 | 说明 |
|---|---|---|
| 新建配方 | `/formulas/new` | 药食同源配方 |
| 实验管理 | `/experiments` | 查看所有实验 |
| 待审核配方 | `/formulas?status=pending_review` | 审核配方方案 |
| AI 智能助手 | `/ai` | 配方生成/分析 |
| 数据库检索 | `/databases` | TCMSP / DFBP |

### 5.2 自定义机制

- 编辑模式：右上角铅笔 → 删除按钮（hover 出现）+「添加快捷入口」虚线按钮
- 添加走 `prompt()` 序列（路径/标题/描述/图标 key）→ `saveActions` 落盘
- 图标 key 白名单（ICON_MAP）：Plus/TestTubes/Clock/Brain/Database/ArrowRight

⚠️ **交互缺陷（P2-01）**：`prompt()` 在部分浏览器/iframe 中会被拦截；建议升级为 Modal 表单。自定义入口的 iconBg/iconColor 统一回落 primary 色（丢失多彩分类色）。

## 6. 加载/错误/重试契约（卡片层统一规范）

| 状态 | 渲染 | 组件 |
|---|---|---|
| 加载中 | 卡片壳保留（标题区可见）+ 内容区 Skeleton（行数 = 预期条数） | `Skeleton` / `CardSkeleton` / `ChartSkeleton` |
| 加载失败 | 整卡替换为错误条 | `ErrorCard`（AlertTriangle 警示图标 + 标题 + 说明 + 重试按钮 ghost） |
| 空数据 | 内容区 EmptyState（图标 + 标题 + 描述 + 可选 CTA） | `EmptyState` |

`renderCard` 为每类卡片注入 `loading / error / onRetry`（对应 React Query refetch 句柄），实现**卡片级错误隔离**：任一数据源失败仅影响对应卡片，整页其余卡片正常渲染。

## 7. 已知问题与改进建议

| 编号 | 问题 | 优先级 | 建议 |
|---|---|---|---|
| C-01 | StatsCards 未接收 `statIndex`，图标/文案全为空 | P0 | renderCard 注入 `props.statIndex`；或 StatsCards 改从 `card.type` 派生 |
| C-02 | 趋势图 `formulasData`/`experimentsData` 接口类型与页面实际传的 `items` 结构不一致（页面额外做 items 映射） | P2 | 统一 `RecentFormulas/RecentExperiments` 直接消费 API 分页响应 |
| C-03 | 图表 X 轴日期格式 `M月D日 周X` 对 90d 周期密度过高 | P2 | 按 period 动态取间隔（每 N 天一个刻度） |
| C-04 | QuickActions 自定义入口 prompt() 交互差、图标色丢失 | P2 | Modal 表单 + 保留原 iconBg/iconColor 序列化 |
| C-05 | 列表卡片「查看全部」仅配方有入口，实验/待办/动态无 | P3 | 统一加「查看全部 → 列表页」 |
| C-06 | 图表 Skeleton 行数与实际数据行数无关（固定值） | P3 | 按 items.length 自适应 |
