# 仪表盘卡片系统与布局管理设计文档

> 对应源码：`frontend/src/config/dashboard.ts`、`frontend/src/pages/formula/components/DashboardLayout.tsx`、`DashboardPage.tsx`
> 定位：仪表盘的**可配置化骨架**——卡片目录、布局模型、拖拽排序、多视图、布局编辑器、预设模板、模板管理。

---

## 1. 核心数据模型

### 1.1 卡片配置（CardConfig）

```ts
interface CardConfig {
  id: string                    // 卡片实例 id（新增：card-<timestamp>）
  type: CardType                // 卡片类型（25 个枚举值）
  title: string                 // 卡片标题
  description?: string
  position: { x, y }            // 逻辑位置（当前网格渲染未使用 x/y，仅保留）
  size: { w, h }                // 网格跨度（CSS grid: gridColumn/Row span）
  isVisible: boolean            // 显隐控制（隐藏卡片在编辑模式下显示虚线占位）
  theme?: 'light' | 'dark' | 'system'   // 卡片级主题
  config?: Record<string, unknown>      // 卡片自定义配置扩展槽
}
```

**卡片类型枚举（CardType，25 种）**：

| 分组 | 类型 |
|---|---|
| 统计 | `stats-formulas`、`stats-experiments`、`stats-in-progress`、`stats-completed` |
| 图表 | `chart-trends`、`chart-formula-pie`、`chart-experiment-bar` |
| 列表 | `recent-formulas`、`recent-experiments`、`todos`、`review-queue`、`activity-timeline`、`quick-actions` |
| AI | `kpi-dashboard`、`ai-insights`、`ai-analysis` |
| 团队 | `team-activity`、`team-dashboard-share`、`team-online-status`、`change-history` |
| 系统 | `websocket-status`、`real-time-sync`、`template-manager`、`export-manager`、`api-integration` |

卡片目录 `CARD_CATALOG` 分两级：
- `default`（13 个）：基础研发管理卡片，所有用户默认可用
- `premium`（12 个）：KPI/团队/AI/实时协作类高级卡片

### 1.2 布局模型（DashboardLayout）

```ts
interface DashboardLayout {
  id: string                   // 'default' | layout_<timestamp> | imported_*
  name: string
  isDefault: boolean           // 全局唯一（saveLayout 时互斥置位）
  cards: CardConfig[]
  createdAt / updatedAt: string
  // 共享字段（当前为前端本地模拟）
  isShared: boolean
  ownerId: string             // 当前恒为 'current-user'
  ownerName: string
  shares: DashboardShare[]    // {id, dashboardId, userId, userEmail, userName, accessLevel}
  lastModifiedBy / lastModifiedAt: string
}
```

### 1.3 默认布局（DEFAULT_CARDS，14 项）

```
Row0: [配方总数][实验总数][进行中实验][完成实验]          （1×1 ×4）
Row1: [研发趋势 w=2][配方状态分布 w=1][实验状态统计 w=1]
Row2: [快捷操作 x=1][AI分析面板 w=2（isVisible=false）]
Row3: [最近配方][最近实验]
Row4: [待办事项][待审核配方][最近动态]
```

设计要点：AI 面板默认**隐藏**（`isVisible: false`），避免 AI 接口不可用时首屏暴露 mock 降级数据；用户可手动开启。

## 2. DashboardConfigManager（localStorage 配置管理器）

Storage keys：`rmfood_dashboard_configs`（布局数组）、`rmfood_current_layout`（当前布局 id）。

| 方法 | 职责 | 健壮性设计 |
|---|---|---|
| `getAllLayouts()` | 读取全部布局 | JSON 解析失败 / 非数组 → 返回 `[DEFAULT_LAYOUT]`；逐卡片结构校验（类型白名单、theme 枚举、数值化 position/size），非法卡片回退 `stats-formulas` 默认卡 |
| `getCurrentLayout()` | 按 `rmfood_current_layout` 取当前布局 | 找不到 → `isDefault` 布局 → `DEFAULT_LAYOUT` |
| `saveLayout(layout)` | 新增/更新布局 | 字段全量白名单化；`isDefault=true` 时其他布局互斥置 false；写失败仅 logger.error（不抛） |
| `switchLayout(id)` | 写 `rmfood_current_layout` | — |
| `createLayout(name, cards?)` | 新建布局（默认克隆 DEFAULT_CARDS） | 返回新布局供 UI 立即使用 |
| `deleteLayout(id)` | 删除布局 | `id==='default'` 禁删；若删的是当前布局则清除 current key |
| `exportLayouts()` | 导出 `{version, exportedAt, layouts}` JSON | — |
| `importLayouts(data)` | 导入布局 | id 冲突时改写 `imported_<ts>_<id>`；结构非法 → false |
| `shareDashboard / removeShare / updateShareAccess / getSharedDashboards / getDashboardByUserId` | 共享管理 | 全部本地 localStorage 模拟；updateShareAccess 使用 `satisfies DashboardShare` 保持类型 |

**已知局限**：`ownerId` 恒为 `'current-user'`，未接入真实用户 id；共享数据不跨端同步（多浏览器/设备间不可见）。

## 3. 可拖拽网格（DashboardLayout 网格组件 + DraggableCard）

### 3.1 网格容器

```tsx
<div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4"
     style={{ gridTemplateColumns: responsive ? undefined : `repeat(${columns}, 1fr)`,
              gap: `${gap}px`, gridAutoFlow: 'row dense' }}>
```

- **响应式模式**（默认）：列数随断点 1→2→3→4，卡片 `size.w` 作为 `gridColumn: span w`。
- **固定模式**（编辑）：`layoutColumns`（2/3/4）+ `layoutGap`（8/16/24）由横幅内嵌控件驱动，`gridAutoFlow: 'row dense'` 自动填充空隙。

### 3.2 DraggableCard 能力

基于 `@dnd-kit` 的 `useSortable`：

| 能力 | 实现 |
|---|---|
| 拖拽重排 | `DndContext`（PointerSensor 5px 激活阈值 + KeyboardSensor 键盘可访问）→ `onDragEnd` 内 `arrayMove` 更新 cards 顺序并落盘 |
| 尺寸调整 | 放大/缩小按钮（w/h ∈ [1,4] / [1,3]） |
| 显隐 | EyeOff 切换 `isVisible`；隐藏卡片渲染虚线占位框（可点击恢复） |
| 主题 | 卡片级 light/dark/system 下拉（写入 `card.theme`） |
| 复制 | `duplicateCard`（新 id、标题加「(副本)」、y+1） |
| 移除 | 编辑模式 X 按钮 → `updateCard(id, {isVisible:false})`（软移除，可恢复） |

注意：`isEditing` 操作栏为 DraggableCard 内部状态（悬停出现设置按钮），而**卡片排序的可用条件**是页面级 `isEditMode`（`disabled={!isEditMode}`）——两层编辑语义需在 UI 上进一步统一（见问题清单 P1-02）。

### 3.3 布局编辑器（LayoutEditor，侧滑抽屉）

- **预设布局模板（PRESET_LAYOUTS，4 套）**：默认布局 / 紧凑布局（小屏）/ 数据聚焦（图表放大）/ 团队协作（在线状态+共享+变更历史）。应用 = 逐个 `onAddCard(type)`（⚠️ 当前实现是**追加**而非替换，见 P1-04）。
- **卡片库**：全部 default+premium 卡片，支持 7 类分类筛选（全部/统计/图表/列表/操作/团队/AI）+ 关键词搜索 + 批量添加。
- **布局提示区**：操作说明。

### 3.4 多视图（LayoutSwitcher）

横幅下拉：列出全部布局（当前高亮 +「默认」徽标），支持切换（`switchLayout`）、创建新视图、删除、设为默认。删除当前视图时回退到默认/首个布局。

## 4. 模板管理（TemplateManager）

Storage key：`rmfood_dashboard_templates`。

| 功能 | 说明 |
|---|---|
| 保存为模板 | 当前 `currentLayout` 快照 + 名称/描述 → 写入本地模板列表 |
| 应用模板 | 以模板 cards 覆盖当前布局（保留 id/name/isDefault），同步 `saveLayout` |
| 导出/导入 | JSON 文件（`{version, exportedAt, template:{layout}}`）；导入校验 `template.layout` 存在 |
| 删除 | 过滤后写回 |

⚠️ 实现缺陷：模板列表初始化误用 `useState(() => {...})`（惰性初始值不执行函数体、且 setTemplates 在渲染期调用），应改为 `useEffect` 挂载加载（见 P0-02 关联问题）。

## 5. 事件与副作用流（布局编辑链路）

```
编辑模式开（isEditMode）
  ├─ 拖拽卡片 ──→ handleDragEnd ──→ arrayMove(cards) ──→ setCurrentLayout + saveLayout
  ├─ 卡片操作栏（内部 isEditing）──→ updateCard / duplicateCard / 尺寸 / 主题 / 隐藏
  ├─ 「添加卡片」──→ LayoutEditor ──→ addCard(type) ──→ 追加 cards + saveLayout
  └─ 列/间距切换 ──→ setLayoutColumns / setLayoutGap（仅会话态，未持久化 ⚠️）
视图切换 ──→ switchLayout(id) ──→ 替换 currentLayout + switchLayout key
导出布局 ──→ exportLayouts() → 手工下载 JSON
```

持久化缺口：`layoutColumns` / `layoutGap` 未写入 CardConfig/DashboardLayout，刷新后回到默认 4/16（P1-05）。

## 6. 设计决策记录

| 决策 | 理由 |
|---|---|
| 卡片注册表 `CARD_COMPONENTS` 替代 switch | 原 ~440 行 switch 难以维护；映射表 + 未知类型 EmptyState 兜底，新增卡片只加 1 行 |
| 编辑模式卡片走「软删除」（isVisible） | 保留卡片可恢复；隐藏卡片在网格中留虚线占位维持布局 |
| localStorage 优先 + DEFAULT_LAYOUT 回退 | 首屏零网络成本；结构校验保证旧版本数据可安全迁移 |
| 非首屏卡片 lazy + Suspense | 团队/AI/导出/AI 集成类重组件不进入首屏 bundle 关键路径 |
| `position{x,y}` 保留不用 | 当前按 DOM 顺序 + span 渲染；保留字段为未来绝对定位模式预留 |
