# 仪表盘 AI 集成模块设计文档

> 对应源码：`frontend/src/pages/formula/components/AIInsights.tsx`（AIInsights + KPIDashboard）、`frontend/src/components/dashboard/AIAnalysisPanel.tsx`、`frontend/src/api/aiInsights.ts`、`frontend/src/hooks/useAIInsights.ts`
> 定位：仪表盘 AI 能力层——洞察生成（前端派生）、KPI 监控、深度分析面板（后端 API + mock 降级）。

---

## 1. 模块总览

仪表盘包含 **3 个 AI 卡片**（均默认在卡片目录中，按布局启用）：

| 卡片 | type | 组件 | 数据源 | 首屏策略 |
|---|---|---|---|---|
| AI 智能洞察 | `ai-insights` | `AIInsights` | 前端从 `/dashboard/statistics` + `/trends` **派生** | 延迟（`enabled: !statsLoading && !trendsLoading`） |
| KPI 监控 | `kpi-dashboard` | `KPIDashboard` | 前端从 `/dashboard/statistics` 派生 | 随卡片 lazy 加载 |
| AI 分析面板 | `ai-analysis` | `AIAnalysisPanel` | 后端 `/ai/*` 4 个 POST 端点；**失败降级 mock** | 默认隐藏（`isVisible:false`） |

外加 `api-integration`（第三方集成管理）卡片 —— 见 04 文档。

## 2. AI 智能洞察（AIInsights）

### 2.1 洞察派生算法（`aiInsightsApi.getInsights`，纯前端规则引擎）

并发请求 `Promise.all([/dashboard/statistics, /dashboard/trends?period=30d])`，按规则生成 4 类洞察：

| 规则 | 触发条件 | 类型 | 影响度 | 置信度 |
|---|---|---|---|---|
| 批准率成就 | `approved > 0` | `achievement` | rate ≥ 70% → high | 0.95 |
| 审核积压异常 | `pending_review > 5` | `anomaly` | >20 → high | 0.90 |
| 失败率异常 | `failed/total > 15%` | `anomaly` | high | 0.85 |
| 进行中实验趋势 | `in_progress > 0` | `trend` | low | 0.92 |
| 配方增速对比 | 近 7 天日均 vs 前 7 天 | `trend` | 变化 >20% → medium | 0.78 |
| 兜底建议 | 无任何洞察时 | `recommendation`「开始积累数据」 | low | 1.0 |

**洞察对象结构（AIInsight）**：
```ts
{ id, type: 'trend'|'anomaly'|'recommendation'|'achievement',
  title, description, impact: 'high'|'medium'|'low',
  confidence: 0-1, timestamp, actionUrl?, actionLabel? }
```

### 2.2 UI 设计

- **分类 Tab**：全部 / 趋势分析 / 异常检测 / 智能建议 / 成就里程碑（`role=tab` + `aria-selected`，全量过滤）
- **洞察卡片**：类型图标（4 色映射）+ 标题 + 影响度 Badge（high=error 色 / medium=warning / low=success）+ 置信度进度条（`aria-valuenow`）+ 操作按钮（`actionUrl` 存在时渲染「查看详情/前往审核」）
- **趋势预测区**（`useAIPredictions`）：2 卡片网格（新增配方 +15% / 实验成功率 +3~5%），up/down/stable 图标 + 变化百分比。⚠️ 预测为**固定启发式**（total×1.15、successRate+3），非真实模型预测（P1-06）。
- **加载态**：父级 loading → CardSkeleton；内部 insightsLoading → 3 条 Skeleton 卡片；error → `ErrorCard`（onRetry = refetchAIInsights）。

### 2.3 KPIDashboard（同文件）

- 数据：`useKPIProgress()` → 前端派生 2 条 KPI：
  - 配方完成率 = `approved/total×100`，目标 85
  - 实验成功率 = `completed/total×100`，目标 80
- 视觉：进度条三态（≥90% success「达标」/ <80% error「需关注」/ 中间 warning「进行中」）+ Badge + 说明文案。
- 问题：`kpi.current` 是百分比数值（0-100），进度条用 `(current/target)*100` 计算时实际应为 `current/target`（**单位混用 bug，P0-03**）；且 KPI 条数为固定 2 条，未接后端 KPI 配置。

## 3. AI 分析面板（AIAnalysisPanel）

### 3.1 架构

```
AIAnalysisPanel（Tabs ×4）
├─ analysis ──── POST /ai/analyze/formula   {formula_id, target_effects}
├─ recommendations POST /ai/recommend/formulas {limit:3}
├─ trends ─────── POST /ai/predict/trends    {timeframe:'30d', metrics}
└─ experiments ── POST /ai/analyze/experiment {experiment_id}
```

- **真实实体取用**：`useFormulas({page:1,page_size:1})` / `useExperiments({page:1,page_size:1})` 取首条 id 作为分析对象；挂载后 `useEffect` 自动触发 analysis + experiment 两个请求（依赖 `formulaId`/`experimentId` 就绪）。
- **Tab 切换驱动请求**：`useEffect([activeTab])` 按 tab 调对应 fetch。
- **mock 降级策略**（4 个端点一致模式）：请求 catch 后按错误类型 log（401/500/离线），随后填充内置 mock 数据，**保证面板任何情况下有内容可展示**。

### 3.2 四个 Tab 的数据契约与 UI

**① 配方分析（FormulaAnalysisResult）**
- 成分分析卡（总成分/药材/肽数量）+ 功效预测卡（置信度 % + Top3 功效 Badge）
- 优化建议列表（ArrowRight 引导）
- 市场分析块（竞争优势 + 目标市场，accent 色底）

**② 智能推荐（Recommendation[]）**
- 推荐卡：名称 + 描述（2 行截断）+ 功效 Badge + 匹配原因 + 相关度 % + 「查看详情」按钮（⚠️ 按钮无跳转，P1-07）

**③ 趋势预测（TrendPrediction）**
- 3 卡指标（配方/实验/成功率：current → predicted + 变化 %）
- 热门功效趋势列表（effect + growth_rate % + 进度条）

**④ 实验分析（ExperimentAnalysisResult）**
- `status==='no_data'` → 空态文案
- 否则：实验状态 Badge（成功/失败）+ 基线提升 % + 关键指标（有效性/稳定性/口感）+ 核心发现 + 下一步建议（Top3）

### 3.3 错误与加载

- 父级 `loading`（页面 isInitialLoading）→ 卡片骨架；父级 `error` → `ErrorCard` + 重试
- 内部 `isLoading` → Loader2 旋转；`error` 状态（仅当 fetch 抛错且无 mock 兜底时）→ 重试按钮（按 activeTab 重发）
- 由于 catch 全走 mock，**「重试」实际永远拿到 mock** —— 用户无法感知后端真实可用性（P1-08：建议 mock 场景加「模拟数据」水印标识）。

## 4. 前端派生 vs 后端计算的边界（设计决策）

| 能力 | 当前实现 | 目标 |
|---|---|---|
| 洞察（4 类） | 前端规则引擎（`aiInsights.ts`） | 保持（数据量小、规则透明、零额外端点） |
| KPI 进度 | 前端固定 2 条 | 后端 KPI 配置化（`POST /kpi/config`） |
| 趋势预测 | 前端固定 +15%/+3% 启发式 | 后端 `/ai/predict/trends` 接入真实模型 |
| 配方/实验深度分析 | 后端端点 + mock 兜底 | 保留，增加 mock 标识 |
| 智能推荐 | 后端端点 + mock 兜底 | 保留；「查看详情」接 `/formulas/:id` |

**置信度字段语义**：`confidence`（0-1）由生成方给出，前端仅做展示（进度条 + %），不用于过滤/排序（排序固定为规则插入序，P2-02：建议按 confidence desc 排序 + 类型 Tab 保留）。

## 5. 已知问题与改进建议

| 编号 | 问题 | 优先级 | 建议 |
|---|---|---|---|
| A-01 | KPIDashboard 进度条 `current/target*100` 单位混用（current 本身已是 %） | P0 | 改为 `current/target` 直接取比 |
| A-02 | AI 预测为固定启发式（+15% / +3%），与「智能」定位不符 | P1 | 接后端模型；前端保留降级 |
| A-03 | 推荐卡「查看详情」无跳转行为 | P1 | 接 `/formulas/${formula_id}` |
| A-04 | mock 数据无标识，用户无法区分真实/模拟 | P1 | mock 场景渲染「模拟数据」Badge 水印 |
| A-05 | AIAnalysisPanel 挂载即并发 2 个请求 + tab 切换再发，重复请求 | P2 | 用 React Query 缓存（`['ai-analysis', tab]`），staleTime 5min |
| A-06 | insights 列表无排序（低置信度可能排在高影响之上） | P2 | 按 confidence desc 稳定排序 |
| A-07 | AIInsights「Beta」Badge 语义：规则引擎已稳定，建议移除或改为「规则版」 | P3 | 文案调整 |

## 6. 测试要点（现有覆盖：`DashboardConfigManager.test.ts` 仅覆盖配置层）

建议补齐：

1. **aiInsights 规则单测**：构造 statistics/trends fixture，断言 6 类规则的触发边界（approved=0 无成就、pending=5 不触发积压、failed 15% 边界、7 天数据不足跳过增速）。
2. **KPIDashboard 数值单测**：current/target 百分比口径修正后回归。
3. **AIAnalysisPanel mock 兜底**：mock apiClient 401/500/网络错误，断言 4 Tab 均渲染 mock 且不抛异常。
4. **A11y**：Tab role/aria-controls/aria-labelledby 已具备，补充键盘操作（左右方向键切 tab）。
