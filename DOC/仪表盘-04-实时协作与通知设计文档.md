# 仪表盘实时协作与通知设计文档

> 对应源码：`frontend/src/services/websocket.ts`、`frontend/src/components/dashboard/{RealTimeSync,TeamOnlineStatus,TeamDashboardShare,ChangeHistory,TemplateManager,ApiIntegrationManager}.tsx`、`frontend/src/pages/formula/components/NotificationCenter.tsx`、`frontend/src/utils/rbac.ts`
> 定位：仪表盘的**协作层**——实时通信（WebSocket 服务与订阅）、通知中心、团队共享 RBAC、在线状态、变更历史、实时同步演示。

## 1. WebSocket 服务（services/websocket.ts）

### 1.1 设计目标

- 单例 `wsService`：连接管理 + 自动重连 + 心跳 + 消息批量 + 频道订阅
- 可降级：`VITE_WEBSOCKET_ENABLED !== true` 时导出 `NoOpWebSocketService`（全 no-op），保证开发/无后端环境可用

### 1.2 连接生命周期

```
connect()
 ├─ 未认证 → 跳过（HttpOnly Cookie 同源携带，不传 URL token）
 ├─ 后端不可达标记（内存 + sessionStorage 5 分钟持久化）→ 直接 resolve(false)
 ├─ new WebSocket(`${VITE_BACKEND_URL 推导 ws}.../api/v1/ws?connection_id&client_info`)
 ├─ onopen → 启动 30s 心跳（ping/pong）、重置重连计数与不可达标记
 ├─ onclose → 非 1000（正常关闭）时 scheduleReconnect
 └─ onerror → 连续失败 ≥5（MAX_CONSECUTIVE_FAILURES）→ 标记后端不可达
                + sessionStorage 写 'ws_backend_unreachable_until'（5 分钟）
                + 错误日志 10s 去重（防刷屏）

scheduleReconnect：指数退避 1s→2s→4s→8s→16s（上限 30s + 随机 1s 抖动），最多 5 次
```

### 1.3 消息处理管线

```
onmessage → JSON.parse（失败 → error 事件）
 ├─ pong / connection_established / error：立即处理（不进批量）
 └─ 其他：batchProcessing=true 时入 messageBuffer → 100ms 批量 flush
      ├─ batchMessageHandlers（批量回调）
      └─ processMessageImmediately：
           user_status → emit('user_status')
           data_update → emit('data_update')
           message.channel → emit(channel, data)（频道匹配：'*' 全匹配 / type 匹配 / data_update.entity_type 匹配）
           + 全部 messageHandlers + 频道订阅 handlers
```

### 1.4 对外 API（仪表盘消费）

| 方法 | 用途 |
|---|---|
| `subscribeToChannel('notifications', fn)` | DashboardPage：未读通知数实时更新 |
| `subscribeToChannel('data_update', fn)` | RealTimeSync：数据变更推送 |
| `wsService.on('user_status', fn)` | TeamOnlineStatus：在线状态 |
| `send(message)` | 手动同步等（未连接时 emit send_failed + 触发重连） |

⚠️ **实现缺陷（P0-04）**：`on(event, handler)` 与 `emit(event, data)` 当前是**日志空壳**——`emit` 只写日志不转发，`on` 只登记不绑定。因此 `wsService.on('user_status')` 与 `emit('connected'/'reconnect_attempt'...)` 均**无实际事件分发效果**，TeamOnlineStatus 的 WebSocket 实时更新路径实际不生效（依赖其 15s 定时器模拟兜底）。修复需实现真正的 EventEmitter 语义。

### 1.5 配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `VITE_BACKEND_URL` | `http://localhost:8000` | 推导 ws 地址（http→ws） |
| `VITE_WS_URL` | 推导值 | 可显式覆盖 |
| `VITE_WEBSOCKET_ENABLED` | 未配置=禁用 | 仅 `'true'`/`'1'` 启用 |

## 2. 通知中心（NotificationCenter）

### 2.1 现状

- **`NotificationBadge`（横幅按钮）**：未读数来自**后端真实接口** `GET /notifications/unread-count`（DashboardPage useEffect + WebSocket `notifications` 频道刷新，WS 禁用时仅挂载时一次）。
- **`NotificationCenter` Modal 列表**：仍为 **`MOCK_NOTIFICATIONS` 5 条硬编码**（配方审核/实验同步/审核提醒/AI 分析/系统更新），未接 `notificationApi.list`（该 API 已存在：`/notifications` + `mark-read`）。
- 支持：按 6 类筛选（system/formula/experiment/review/alert/ai）、关键词搜索、未读高亮（primary 底色 + 左上圆点）、相对时间格式化（刚刚/N分钟前/N小时前/N天前/日期）、标已读/全部已读/归档/删除（仅本地 state，刷新丢失）。

### 2.2 目标设计

```
NotificationCenter
├─ 数据源：notificationApi.list({page, page_size:20, status:'unread'})
├─ 操作：markAsRead → POST /notifications/mark-read（失效后刷新 unread-count）
├─ 分页/滚动加载：滚动到底拉取下一页
└─ 筛选/搜索：type 映射（后端 type → 6 类前端标签）
```

## 3. 团队共享（TeamDashboardShare + RBAC）

### 3.1 权限模型（utils/rbac.ts）

**仪表盘访问级别（AccessLevel，三级）**：

```
view   → [VIEW]
edit   → [VIEW, EDIT, DELETE]
admin  → [VIEW, EDIT, DELETE, SHARE, MANAGE_PERMISSIONS, ADMIN]
```

- `RBAC.getUserAccessLevel(userId, ownerId, shares)`：owner → `admin`；有 share 记录 → 对应级别；无记录 → `view`
- 协作角色矩阵（CollaborationRole：owner/editor/reviewer/viewer）用于文档协作场景，与仪表盘共享为两套并行模型。

### 3.2 共享功能（前端本地模拟）

| 功能 | 实现 |
|---|---|
| 邀请成员 | 对话框：邮箱（在 mock 成员列表中匹配）+ 级别（view/edit/admin）→ `DashboardConfigManager.shareDashboard` 写 localStorage |
| 成员列表 | 显示 shares（头像首字 + 级别 Badge） |
| 移除/改级 | `removeShare` / `updateShareAccess`（当前 UI 未暴露入口 ⚠️ P1-09） |
| 权限门控 | `canShare`/`canManagePermissions` 控制「邀请成员」按钮禁用态 |

**局限**：成员列表为 mock（张三/李四/王五/赵六），ownerId 恒为 `current-user`；无跨用户同步（P1，依赖后端 team 模块——`backend/app/api/v1/team_dashboard_router.py` 已提供 `/teams/{team_id}/dashboard` 与 `/teams/{team_id}/activity` 端点，具备接入基础）。

### 3.3 设计目标（后端接入路径）

```
当前：DashboardConfigManager（localStorage）+ mock 成员
目标：/teams/{team_id}/dashboard（后端持久化共享）
      + WebSocket /api/v1/ws/notifications/{team_id}（共享变更推送）
      + RBAC 后端强制校验（前端 UI 门控 → 后端 403 兜底）
```

## 4. 团队在线状态（TeamOnlineStatus）

- **UI**：成员列表（首字头像 + 在线状态点 online=success / away=warning / offline=neutral）+ 当前操作文案（编辑布局/查看数据/添加卡片…对应 lucide 图标）+ 3 格统计（在线/离开/离线）+ 协作提示卡。
- **数据**：初始化 mock 3 用户；`wsService.on('user_status')`（当前空壳，不生效）+ **15s 定时器随机化状态/操作**兜底演示。
- **目标**：后端 heartbeat 上报（连接建立/30s 心跳）+ 真实用户状态事件，移除模拟定时器。

## 5. 变更历史（ChangeHistory）

- **数据结构**：`ChangeEvent{id, userId, userName, timestamp, action(create/update/delete/share/permission), entityType(dashboard/card/layout), entityId, entityName, description, details}`
- **UI**：搜索 + 操作/用户双 Select 筛选 + 时间线列表（动作图标 + 相对时间 + details JSON 折叠）+ 5 格动作统计（创建/更新/删除/共享/权限）。
- **数据源**：当前为 **useEffect 内 5 条 mock**（P1-10：应接后端 audit log 端点；`backend/app/api/activity.py` 已查 AuditLog 模型，具备数据源）。

## 6. 实时数据同步（RealTimeSync）

- **功能**：订阅 `data_update` 频道 + **5s 定时器模拟** create/update/delete 事件 → 同步历史列表（最近 10 条，新到顶部）+ 计数 Badge + 最后同步时间 + 手动同步按钮。
- **定位**：实时能力**演示卡**（文案明确「实时数据同步演示」）；生产化需移除模拟定时器、事件真实化、历史持久化。

## 8. 已知问题与改进建议

| 编号 | 问题 | 优先级 | 建议 |
|---|---|---|---|
| R-01 | `WebSocketService.on/emit` 为空壳，`user_status`/`connected` 等事件实际不分发 | P0 | 实现事件表（Map<string, Set<Handler>>），emit 遍历分发 |
| R-02 | 通知中心 Modal 为 mock 数据，后端 API 已备而未接 | P1 | 接 `notificationApi.list/markRead`，操作后 invalidate 未读数 |
| R-03 | 团队共享/在线状态/变更历史均为前端 mock，ownerId 固定 | P1 | 接 team 端点 + WebSocket 推送 + 真实 auth user id |
| R-04 | ChangeHistory 无后端数据源 | P1 | 接 audit log 端点（后端 AuditLog 模型已存在） |
| R-05 | 通知 Modal 操作（已读/归档/删除）刷新即丢 | P2 | 随 R-02 后端化后自然解决 |
| R-06 | RealTimeSync/TeamOnlineStatus 的模拟定时器在无 WS 环境持续运行 | P2 | `wsService.getIsConnected()` 为 false 时显示「实时连接未启用」而非伪造数据 |

## 9. 降级策略总结（协作层可用性设计）

| 场景 | 表现 |
|---|---|
| WS 未启用（默认） | NoOp service：未读数仅挂载时拉一次；实时同步卡演示定时器继续跑；通知中心静态 mock |
| 后端不可达（连续 5 次失败） | 5 分钟内停止重连（sessionStorage 标记），刷新页面清除 |
| 部分卡片数据失败 | 卡片级 ErrorCard（见 02 文档），协作卡不阻塞主数据区 |
| 权限不足 | RBAC UI 门控（邀请按钮禁用），后端 403 兜底（目标态） |
