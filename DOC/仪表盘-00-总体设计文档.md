## 1. 页面定位与架构总览

仪表盘是「食源性药食同源配方平台」的**首屏入口页**，承担以下职责：

1. **数据总览**：配方/实验的数量统计、状态分布、研发趋势（KPI 监控）
2. **任务驱动**：待办事项、待审核队列、最近动态时间线
3. **智能增强**：AI 智能洞察、KPI 进度监控、AI 深度分析面板（配方/实验/推荐/趋势）
4. **个性化配置**：卡片目录、多视图布局、可拖拽排序、列/间距调整、模板管理、布局导入导出
5. **团队协作**：团队共享、在线状态、变更历史、实时数据同步（WebSocket）
6. **全局工具**：全局搜索、通知中心、数据导出（CSV）、全局刷新

### 1.1 技术栈

| 类别 | 选型 |
|---|---|
| 框架 | React 18 + TypeScript + Vite |
| 路由 | react-router-dom（Link / useNavigate） |
| 状态管理 | Zustand（`useAuthStore`）+ React Query（@tanstack/react-query） |
| 图表 | recharts（AreaChart / PieChart / BarChart） |
| 拖拽 | @dnd-kit/core + @dnd-kit/sortable |
| 图标 | lucide-react |
| UI 基元 | 自研 `@/components/ui`（Card / StatCard / Button / Badge / Skeleton / Modal / Tabs…） |
| 实时通信 | WebSocket（`@/services/websocket`，默认禁用，需 `VITE_WEBSOCKET_ENABLED=true`） |
| 配置持久化 | localStorage（`rmfood_dashboard_configs` / `rmfood_current_layout` / `rmfood_quick_actions` / `rmfood_dashboard_templates`） |

## 3. 数据流设计

### 3.1 首屏数据（阻塞，触发全局骨架）

| 数据 | Hook | 端点 | staleTime |
|---|---|---|---|
| 综合统计 | `useDashboardStatistics` | `GET /dashboard/statistics` | 5min |
| 研发趋势（30d 固定） | `useDashboardTrends` | `GET /dashboard/trends?period=30d` | 5min |
| 最近配方（5条） | `useFormulas({page:1,page_size:5})` | `GET /formulas` | — |
| 最近实验（5条） | `useExperiments({page:1,page_size:5})` | `GET /experiments` | — |

`isInitialLoading = statsLoading || trendsLoading || formulasLoading || experimentsLoading`
→ 为 true 时渲染 `<DashboardSkeleton />`，替换整块内容区。

### 3.2 延迟加载数据（`enabled: !statsLoading && !trendsLoading`，不阻塞首屏）

| 数据 | 端点 | 说明 |
|---|---|---|
| 活动时间线（7天） | `GET /activity/timeline?days=7` | staleTime 5min |
| 待办事项 | `GET /activity/todos` | 按角色聚合 |
| 审核队列 | `GET /activity/review-queue` | 待审核配方 |
| AI 洞察 | `GET /dashboard/statistics + /trends` 前端派生 | `aiInsightsApi.getInsights` |
| 通知未读数 | `GET /notifications/unread-count` | 挂载时请求 |

### 3.3 实时通道（WebSocket，可选）

- `subscribeToChannel('notifications', ...)`：收到 `notification.created` / `notification.marked_read` 时重新拉取 unread-count。
- `RealTimeSync` 组件订阅 `data_update` 频道；当前组件内还叠加 5s 定时器模拟数据变更。
- `TeamOnlineStatus` 监听 `user_status` 事件；叠加 15s 定时器模拟状态漂移。
- 全部组件由 `lazy(() => import(...))` + `<Suspense fallback={<CardSkeletonComp/>}>` 延迟加载，非首屏卡片零首屏成本。

### 3.4 布局状态（localStorage 优先）

```
DashboardConfigManager.getCurrentLayout()
  └─ rmfood_dashboard_configs（全部布局数组）+ rmfood_current_layout（当前 id）
     读取失败 / 结构非法 → 回退到 DEFAULT_LAYOUT（13 卡片 + 1 隐藏 AI 面板）
编辑动作：
  handleDragEnd（排序）/ updateCard（显隐、尺寸、主题）/ addCard / duplicateCard
  → setCurrentLayout + DashboardConfigManager.saveLayout（写回 localStorage）
```

## 4. 卡片渲染分发机制（renderCard）

`DashboardPage` 中 `CARD_COMPONENTS` 映射表（20 个 type）替代了旧的 ~440 行 switch：

1. **props 准备阶段**：按 `card.type` 向前置数据装配 props（统计卡片按 `statIndexMap` 取 total；图表卡片取 trends/stats；列表卡片取 items + loading + error + onRetry）。
2. **布局依赖卡片**：`team-dashboard-share / team-online-status / change-history / template-manager` 走独立 `renderXxx()` 函数（需要 currentLayout/setCurrentLayout/dashboardId）。
3. **兜底**：未知类型渲染 `EmptyState`「即将上线」。

`CardRenderProps` 接口（~50 字段）是卡片与页面之间唯一的契约，所有 loading/error/refetch 状态显式透传，保证卡片级错误隔离（单卡片失败不影响整页）。

## 5. 状态管理与副作用设计

| 状态 | 类型 | 说明 |
|---|---|---|
| `currentLayout` / `layouts` | React state（localStorage 初始化） | 当前/全部布局 |
| `isEditMode` / `showEditor` | boolean | 编辑模式与卡片编辑器 |
| `layoutColumns(4)` / `layoutGap(16)` | number | 网格列数/间距（仅编辑模式可见） |
| `searchQuery` / `searchResults` / `showSearch` | string[]/boolean | 全局搜索（300ms 防抖） |
| `notificationCount` / `showNotifications` | number/boolean | 通知中心 |
| `trendPeriod` | `'30d'`（当前固定） | 趋势周期（UI 上尚无切换器，periodOptions 已配置 7d/30d/90d 待接入） |

副作用：
- `useEffect` ×2：挂载时拉未读通知数；订阅 WebSocket `notifications` 频道（cleanup 中 unsubscribe）。
- 所有 React Query refetch 句柄显式下传，横幅「刷新」按钮统一触发 4 路 refetch。

| 项 | 规范 |
|---|---|
| 根节点 | `min-h-screen bg-grid`（点状网格背景）+ `backgroundColor: var(--bg-canvas)` |

| 欢迎横幅 | `surface-primary rounded-xl p-6 shadow-sm`，白字，含搜索胶囊（`bg-white/15 rounded-full`）与 ghost/secondary 按钮 |
| 统计卡片 | `StatCard`（Card 包裹 + 顶部 accent bar + 图标 + 标签 + 数值） |
| 图表 tooltip | `var(--card-bg-solid)` 背景、`--border-color` 描边、CSS 变量取色（`--color-success` 等） |
| 骨架屏 | `DashboardSkeleton`（横幅 4 区 + 统计 4 卡 + 图表 3 卡 + 底部 4 卡 + AI 洞察占位） |
| 暗色模式 | 全部卡片 dark: 类成对书写；图标取色 `text-neutral-400 dark:text-neutral-500` |

## 7. 后端 API 契约（仪表盘消费端点）

| 端点 | 方法 | 返回 | 认证 |
|---|---|---|---|
| `/dashboard/statistics` | GET | `{formulas:{total,by_status}, experiments:{total,by_status}, users:{total,by_role}, recent_activity[30]}` | 登录用户 |
| `/dashboard/trends?period=7d\|30d\|90d` | GET | `{period, data:[{date, formulas_created, experiments_created, formulas_approved}]}` | 登录用户 |
| `/activity/timeline?days=N` | GET | `{items:[{id,type,title,status,created_at,event}], total}` | 登录用户 |
| `/activity/todos` | GET | 角色聚合待办（reviewer/admin 含审核项；个人含进行中/计划中实验） | 登录用户 |
| `/activity/review-queue` | GET | `{items:[{id,name,code,creator_name,target_effects,submitted_at}], total}` | 登录用户 |
| `/notifications/unread-count` | GET | `{count}` | 登录用户 |
| `/formulas` / `/experiments` | GET | 分页列表（首 5 条） | 登录用户 |
| `/ai/analyze/formula`、`/ai/recommend/formulas`、`/ai/predict/trends`、`/ai/analyze/experiment` | POST | AIAnalysisPanel 消费；失败时前端降级 mock | 登录用户 |

后端实现要点（`backend/app/api/dashboard.py`）：使用 `text()` 原生 SQL 统计，规避 ORM 枚举与 varchar 列不匹配；状态分布按默认状态集填充 0 值，保证前端 `by_status` 键稳定。`/trends` 逐日循环查询（30/90 天 = 30/90 次 DB 往返，为已知性能改进点）。
