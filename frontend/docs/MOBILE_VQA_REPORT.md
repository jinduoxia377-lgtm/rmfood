# 移动端视觉规范核查与修复报告（2026-10-20 第四轮）

> 背景：用户真机测试反馈移动端仍有「不规范」问题。此前多轮自动化审计（溢出/字号/按钮高度）均全绿，但用户仍不满意——说明**量化脚本无法覆盖视觉规范性**。本轮新增 `scripts/audit-mobile-vqa.mjs`（iPhone 13 视口，检测桌面式布局残留），逐页定位真实问题并修复。

## 一、先承认：此前核查方法的局限

- 之前核查基于「可测量指标」：横向溢出、最小字号、按钮高度、网格列宽——这些**全部达标**；
- 但「移动端规范」还包括：表单控件是否占满、双列布局是否过窄、内边距/间距是否过大、横幅是否过高、是否有桌面式固定宽度残留——这些是用户真机感受到的「不规范」来源，脚本之前未覆盖。

## 三、复测结果（30 路由）

- **真实问题全部解决**：peptide-structure、settings、labels 问题消失；compliance 输入框 48%→64%、workflows 53%→61%。
- **剩余标记均为脚本误报/合理模式**：
  - `tall-banner card`（12 页）：首张白卡片被误判为横幅（非品牌色块）；
  - 真实品牌横幅（/formulas 230px、/workflows 228px、/agent 249px）：移动端含标题+副标题+搜索/按钮，高度合理；
  - `/users` 12 列日志表 `min-w-[960px]`：日志型表格横向滚动为常见模式；
  - `/doe` 文件上传控件 50%、`/stability` 双字段并排 52%：属表单固有布局。
