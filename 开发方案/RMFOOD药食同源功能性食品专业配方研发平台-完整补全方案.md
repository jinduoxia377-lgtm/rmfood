### 1.1 平台功能架构总览

RMFOOD药食同源功能性食品专业配方研发平台是一个面向功能性食品研发的全生命周期管理平台。平台以"药食同源"理念为核心，整合中药学、营养学、分子生物学等多学科知识，为研发团队提供从原料筛选、配方设计、功效评估到合规审查的完整解决方案。

### 1.2 配方管理模块 (Formula Management Module)

#### 1.2.1 模块职责与定位

配方管理模块是平台的核心模块，承担着配方全生命周期管理的职责。模块以配方实体为中心，向上对接原料数据库获取成分信息，向下关联实验模块支撑研发验证，同时与AI服务模块协同实现智能配方推荐。

模块设计遵循GMP（良好作业规范）的质量管理理念，确保配方数据的完整性、可追溯性和合规性。配方状态机严格遵循DRAFT→PENDING_REVIEW→APPROVED/REJECTED的流转规则，每个状态转换都有完整的审计日志。

#### 1.2.2 核心功能详细设计

**配方创建与编辑功能**采用所见即所得的设计理念。配方师在创建界面可以实时预览配方的整体结构，包括成分组成、功效定位、工艺参数等关键信息。编辑功能支持版本化管理，每次保存自动生成版本快照，确保历史修改可追溯。

成分添加采用智能推荐机制。系统会根据当前配方功效定位，自动从原料数据库中筛选符合条件的候选成分，并以优先级排序展示。配方师可以一键添加推荐成分，也可以手动搜索添加。

配方模板功能允许企业维护标准配方模板库。新配方创建时可以直接从模板导入，继承模板的基础结构和默认参数，大幅减少重复工作。模板支持版本管理，不同版本可以对应不同的产品线或市场定位。

配方对比功能支持同时打开多个配方进行横向比较。系统从功效、成本、稳定性、合规性等多个维度生成对比报告，帮助决策者快速评估不同配方的优劣。

### 1.3 实验管理模块 (Experiment Management Module)

#### 1.3.1 模块职责与定位

实验管理模块负责管理功能性食品研发过程中的实验全生命周期。模块与配方模块深度集成，支持从配方到实验的快速跳转，实验结果可以反向验证配方设计的合理性。

实验模块采用LIMS（实验室信息管理系统）的设计理念，确保实验数据的规范性、完整性和可追溯性。每个实验创建时必须关联目标配方，实验过程中采集的数据自动与配方版本绑定。

#### 1.3.2 核心功能详细设计

实验计划功能支持结构化定义实验目标、方法、材料和预期结果。系统提供常用实验模板，研发人员可以快速创建标准实验。实验日历视图直观展示实验进度，帮助团队协调资源分配。

数据采集功能支持多种数据格式的录入，包括数值型、文本型、图片型和附件型。数值型数据支持批量导入和自动校验，异常数据自动标记。图片型数据支持缩略图预览和多维度标注。

数据可视化功能提供丰富的图表类型，包括折线图、柱状图、散点图、热力图等。图表配置支持灵活定制，数据维度可以自由组合。导出的图表可以直接用于研发报告。

实验报告功能自动汇总实验元数据、过程数据和结果分析，生成标准化的实验报告模板。报告支持多格式导出（PDF、Word、HTML），满足不同场景的使用需求。

### 1.4 AI智能服务模块 (AI Intelligence Service Module)

#### 1.4.1 模块职责与定位

AI智能服务模块是平台的核心竞争力模块，为配方研发提供全方位的人工智能支撑。模块整合多个专业AI模型，覆盖配方生成、功效预测、安全评估、成本优化等关键场景。

模块采用微服务架构，各AI模型独立部署和扩展。模型推理支持GPU加速，确保复杂推理任务的响应速度。异步任务机制确保长时间推理不影响用户体验。

#### 1.4.2 AI模型矩阵

| 模型名称 | 核心能力 | 适用场景 | 性能指标 | 部署方式 |
|----------|----------|----------|----------|----------|
| FormulaGPT | 配方智能生成与优化 | 从功效描述生成配方方案 | BLEU≥0.82, 合规率99.2% | vLLM推理服务 |
| SynergyNet | 成分协同作用分析 | 预测成分间协同与拮抗效应 | AUC≥0.91, F1≥0.87 | PyTorch Serving |
| PeptideScorer | 活性肽功效预测 | 预测肽序列的生物活性 | Pearson r≥0.89 | ONNX Runtime |
| TastePredictor | 口感与风味预测 | 预测产品的感官特性 | RMSE≤0.15, R²≥0.88 | Scikit-learn Serving |
| StabilityModel | 货架期稳定性预测 | 预测产品在不同条件下的稳定性 | MAE≤2.3% (12月) | TorchServe |
| SafetyChecker | 安全合规自动审查 | 药食同源目录校验、风险筛查 | 召回率≥99.5% | FastAPI内嵌 |

#### 1.4.3 智能配方生成流程

智能配方生成采用多阶段推理架构。首先，FormulaGPT根据用户输入的功效描述生成多个候选配方方案；其次，SynergyNet对每个候选方案进行协同效应分析；接着，SafetyChecker进行合规性和安全性审查；最后，系统综合各维度评分输出最优方案。

生成结果包含完整的配方信息、功效论证、风险提示和优化建议。用户可以直接将结果保存为配方草稿，也可以进一步编辑调整。

### 1.6 工作流与审批模块 (Workflow & Approval Module)

#### 1.6.1 模块职责与定位

工作流与审批模块负责管理配方研发过程中的各种业务流程，包括配方审核流程、实验审批流程、数据导出审批流程等。模块采用BPMN 2.0标准设计，确保流程定义的规范性和可扩展性。

模块内置灵活的工作流引擎，支持复杂的多级审批、会签、加签、转交等场景。流程状态实时追踪，超时自动提醒，确保业务高效流转。

#### 1.6.2 配方审核流程设计

配方审核流程采用三级审批机制，确保配方的科学性、合规性和商业价值都得到充分评估。

```
发起人提交
     │
     ▼
一级审核：技术审核
├── 审核要点：配方科学性、功效论证充分性、数据完整性
├── 审核人：资深配方师或研究员
├── 时效要求：2个工作日内完成
└── 否决条件：功效定位不明确、关键数据缺失
     │
     ├─通过→ 二级审核：合规审核
     │         ├── 审核要点：法规合规性、标签合规性、安全风险
     │         ├── 审核人：法规专员或合规经理
     │         ├── 时效要求：3个工作日内完成
     │         └── 否决条件：成分超出药食同源范围、添加剂超标
     │              │
     │              ├─通过→ 三级审核：商业审核
     │              │         ├── 审核要点：成本合理性、市场定位、可规模化
     │              │         ├── 审核人：产品经理或商务总监
     │              │         ├── 时效要求：5个工作日内完成
     │              │         └── 否决条件：成本无竞争力、目标市场模糊
     │              │              │
     │              │              └─通过→ 审批通过，状态变更为APPROVED
     │              │
     └─否决→ 返回发起人，状态变更为REJECTED，附审核意见
```

## 第三部分：配方研发流程专业设计

### 3.1 研发流程总体架构

配方研发流程采用Stage-Gate模型设计，将研发过程划分为多个阶段，每个阶段结束时设置评审关口，只有通过评审才能进入下一阶段。这种设计确保研发资源集中于有潜力的项目，同时尽早识别和规避风险。

│  Stage 1        Stage 2        Stage 3        Stage 4        Stage 5             │

│                                                                                     │
│    │              │              │              │              │                │
│    ▼              ▼              ▼              ▼              ▼                │

### 3.2 各阶段详细设计

#### 3.2.1 概念验证阶段 (Stage 1: Concept Validation)

概念验证阶段是研发项目的起点，目标是评估市场需求的真实性和技术实现的可行性。配方师需要收集目标市场的消费者洞察、竞品分析和法规要求，同时进行初步的技术可行性评估。

阶段产出包括市场调研报告、竞品分析报告、技术可行性评估报告和项目立项申请书。所有文档通过Gate 1评审后，项目正式立项进入配方设计阶段。

#### 3.2.2 配方设计阶段 (Stage 2: Formula Design)

配方设计阶段是研发过程的核心环节，目标是完成配方的初步设计和验证。配方师根据目标功效定位，从原料数据库中筛选候选原料，通过AI辅助设计多组候选配方方案。

配方设计支持两种模式：智能生成模式和手动设计模式。智能生成模式下，配方师输入目标功效描述，系统自动生成多个候选配方方案；手动设计模式下，配方师从原料库中自主选择原料并设定配比。

配方设计阶段需要进行初步的功效论证和安全性评估。系统提供功效预测工具，可以快速评估配方可能带来的功效；SafetyChecker自动进行合规性检查，识别潜在的法规风险。

阶段产出包括配方设计报告、AI推荐分析报告、初步功效论证报告和安全性评估报告。所有文档通过Gate 2评审后，进入配方优化阶段。

#### 3.2.3 配方优化阶段 (Stage 3: Formula Optimization)

配方优化阶段的目标是通过小试实验验证配方的可行性，并根据实验结果进行优化调整。研究员根据配方设计阶段的产出，进行原料预处理工艺研究、提取工艺优化、成型工艺研究等工作。

小试实验需要严格按照实验方案执行，实验过程中的所有数据都需要规范记录。系统提供实验数据采集功能，支持数值、文本、图片等多种数据格式的录入。

实验数据通过分析工具进行处理，生成功效数据报告、成本分析报告和稳定性初评报告。基于实验结果，配方师对配方进行优化调整，可能需要返回配方设计阶段重新设计。

阶段产出包括小试实验报告、工艺参数优化报告、功效验证报告和成本分析报告。所有文档通过Gate 3评审后，进入功效验证阶段。

#### 3.2.4 功效验证阶段 (Stage 4: Efficacy Verification)

功效验证阶段的目标是通过中试规模实验全面验证配方的功效性、稳定性和安全性。中试规模通常是小试规模的100倍以上，更接近实际生产条件。

功效验证需要进行体内外实验，包括动物实验、细胞实验和临床前安全性评价。实验方案需要经过伦理委员会审批，实验过程需要符合GLP（良好实验室规范）要求。

阶段产出包括中试实验报告、功效验证报告、安全性评价报告和稳定性研究报告。所有文档通过Gate 4评审后，进入商业化准备阶段。

#### 3.2.5 商业化准备阶段 (Stage 5: Commercialization Ready)

商业化准备阶段的目标是完成配方从研发到生产的转移，确保配方可以在生产条件下稳定复制。研发团队需要与生产团队紧密协作，完成生产工艺的放大验证和质量标准的制定。

阶段产出包括生产工艺规程、质量标准操作规程、产品规格书和注册申报资料。所有文档通过Gate 5评审后，配方正式获得生产许可，可以投入商业化生产。

### 3.3 配方研发协同机制

配方研发涉及多个角色的协作，包括配方师、研究员、功效评估师、法规专员和产品经理。平台通过以下机制确保协作高效：

### 5.2 权限控制实现

#### 5.2.1 API层权限控制

API层权限控制采用FastAPI依赖注入机制，每个需要权限验证的API端点声明所需的权限依赖。

```python
from fastapi import Depends, HTTPException, status
from typing import Annotated

class Permission:
    """权限验证依赖"""
    def __init__(self, required_permissions: list[str]):
        self.required_permissions = required_permissions

    async def __call__(
        self,
        current_user: User = Depends(get_current_active_user)
    ) -> User:
        for permission in self.required_permissions:
            if not current_user.has_permission(permission):
                raise HTTPException(
                    status_code=status.HTTP_403_FORBIDDEN,
                    detail=f"权限不足: 需要 {permission}"
                )
        return current_user

# 使用示例
@router.post("/formulas", dependencies=[Depends(Permission(["formula:create"]))])
async def create_formula(...): ...

@router.post("/formulas/{id}/review", dependencies=[Depends(Permission(["formula:review"]))])
async def review_formula(...): ...
```

#### 5.2.2 数据层级权限控制

数据层级权限控制确保用户只能访问有权访问的数据。权限判断基于数据的创建者、所属团队和数据分类属性。

```python
async def check_data_access(
    user: User,
    resource_type: str,
    resource_id: int
) -> bool:
    """检查用户对特定数据的访问权限"""
    # ADMIN拥有对所有数据的访问权限
    if user.role == Role.ADMIN:
        return True

    # 获取资源信息
    resource = await get_resource(resource_type, resource_id)

    # 资源创建者拥有完全访问权限
    if resource.creator_id == user.id:
        return True

    # REVIEWER可以查看所有配方
    if resource_type == "formula" and user.role == Role.REVIEWER:
        return True

    # 检查团队权限
    if user.team_id == resource.team_id:
        return True

    # 检查数据分类权限
    if resource.classification in user.authorized_classifications:
        return True

    return False
```

#### 6.3.2 药食同源目录实时校验

SafetyChecker模块内置药食同源目录数据库，实时校验配方成分是否在官方许可范围内。

```python
class FoodHomologyChecker:
    """药食同源目录校验器"""
    def __init__(self):
        self.catalog = self._load_official_catalog()
        self.last_updated = "2024-01-01"

    def check_ingredient(self, ingredient_name: str) -> ValidationResult:
        """检查成分是否在药食同源目录范围内"""
        normalized_name = self._normalize_name(ingredient_name)

        # 精确匹配
        if normalized_name in self.catalog.exact_match:
            return ValidationResult(
                is_permitted=True,
                category="EXACT_MATCH",
                daily_limit=self.catalog.get_limit(normalized_name)
            )

        # 别名匹配
        alias_match = self.catalog.find_by_alias(normalized_name)
        if alias_match:
            return ValidationResult(
                is_permitted=True,
                category="ALIAS_MATCH",
                daily_limit=alias_match.limit,
                warnings=[f"别名: {alias_match.official_name}"]
            )

        # 未找到匹配
        return ValidationResult(
            is_permitted=False,
            category="NOT_FOUND",
            suggestions=self._find_similar(normalized_name)
        )

    def check_dosage(self, ingredient: str, dosage: float, unit: str) -> ValidationResult:
        """检查成分日用量是否在允许范围内"""
        limit = self.catalog.get_limit(ingredient)
        if limit and dosage > limit.max_daily:
            return ValidationResult(
                is_permitted=False,
                category="EXCEEDS_LIMIT",
                message=f"日用量 {dosage}{unit} 超过最大限量 {limit.max_daily}{unit}"
            )
        return ValidationResult(is_permitted=True)
```
