## 二、后端修复明细

### 1. AuditLog 构造错误（P0-1 / P0-2）
`AuditLog` 实体实际列是 `resource_type/resource_id`，`entity_type/entity_id` 只是只读 property。已修复所有构造点：
- `backend/app/services/user.py` `_audit_log`：`entity_type/entity_id` → `resource_type/resource_id`
- `backend/app/services/formula/formula_module.py` `_audit_log`：同上
- `backend/app/api/formulas.py` 批量日志/批量删除日志：同上，并把 `username/user_role/method/path/status_code` 等非表字段合并进 `details` JSON

### 2. CSV 批量导入（P0-3）
- `backend/app/api/admin.py` `batch_import_users`：`file` 参数改为 `file: UploadFile = File(...)`
- 角色映射对齐后端枚举：`admin/reviewer/researcher/formulator/guest`（CSV 中大小写均可，内部统一转小写）

### 3. 角色枚举统一（P0-4 / P0-5）
- 后端角色保持不变：`guest/researcher/formulator/reviewer/admin`（存库为枚举名大写）
- `list_users` 角色筛选：`cast(User.role, String) == role_enum.name`，解决 `varchar = userrole` 操作符不存在问题
- `update_user_role`：前端改为传小写值后可直接 `UserRole(role)` 转换

### 4. 越权修复（P1-1）
- `backend/app/api/users.py` `get_user` / `update_user`：依赖改为 `get_current_active_user`，并校验 `本人 或 ADMIN`，否则 403

### 5. 活动历史（P1-2）
- `backend/app/api/activity.py` `/activity/timeline` 新增 `user_id` 查询参数：
  - 非管理员默认只看自己；管理员可指定任意用户
  - 按用户过滤配方（creator_id）与实验（researcher_id），指定用户时不再返回全局术语/分类事件

### 6. 注册趋势字段（P1-3）
- 前端读取 `d.period || d.date || d.time`（后端返回 `period`）

### 7. 组织筛选（P1-4）
- `UserResponse` 新增 `organization_id / organization_name` 字段
- `list_users` 新增 `organization_id` 过滤参数，组织名称通过原生 SQL 查询真实 `organizations` 表
- `GET /admin/users/organizations` 改为真实组织表聚合（含 user_count）
- 顺带修复 `backend/app/models/organization.py` 与 `api_key.py` 的 `BigInteger` 未导入、关系缺 `foreign_keys` 的潜在崩溃问题

### 8. 服务端排序（P2-1）
- `list_users` 新增 `sort_field / sort_dir`（白名单：username/full_name/role/created_at/last_login）

### 9. 搜索增强（P2-7）
- `list_users` 搜索范围从"用户名/姓名"扩展为"用户名/姓名/邮箱"
