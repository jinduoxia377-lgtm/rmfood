# RMFOOD 多智能体协作「专业群聊」产品设计方案（v1）

> 状态：待评审实施
> 设计者：平台架构/产品专家
> 目标：把当前"任务群聊"升级为**专业的研发协作空间**——消息、任务、人员、工具、过程与结果一体化的群聊产品。

---

## 一、产品定位

**专业群聊 = 研发协作工作台**。它不仅是消息列表，而是：
- **任务的容器**：每个任务群 = 一个研发项目空间（目标、成员、过程、成果都在群里）；
- **人机协作场**：用户 + Chief + 专家 Bot 在同一空间实时协作；
- **能力的市场**：团队缺人/缺工具时，系统自动从角色库或 GitHub 实时补充；
- **可追溯的过程**：派单计划、每步执行、失败重试、最终方案全部留痕。

**设计原则**：
1. 确定性 > 自由发挥：LLM 只做规划与汇总，执行是确定性工作流；
2. 过程可见：每个动作（派单/招募/执行/失败/重试）都有消息与状态；
3. 成员一致：建群配人、派单执行、成员管理三方一致；
4. 一次点击完成：用户只输入任务，其余自动。

---

## 二、信息架构

```
/agent（智能协作）
 ├── Bot 列表
 ├── Chief 控制台
 ├── 群聊协作
 │     ├── 群聊列表（左栏）
 │     │     ├── 任务群（任务卡片：状态/进度/专家数/归档）
 │     │     └── 手动群
 │     └── 群聊工作台（主区）
 │           ├── 群头部：任务摘要 + 状态徽标 + 操作（追加专家/归档/重新派单）
 │           ├── 消息流（结构化消息：系统/派单/结果/汇总）
 │           └── 输入区（@ 定向 + 引用 + 发送）
 └── 任务中心
       ├── 任务列表（全部/进行中/已完成/失败/已归档）
       └── 任务执行视图（任务信息 + 群聊消息流 + 状态自动刷新）
```

**决策**：任务中心与群聊协作共用同一个群聊工作台组件（`GroupChatView`），任务状态为权威来源。

---

## 三、核心功能设计

### 1. 结构化消息类型（专业群聊的关键）

消息流不再只是纯文本，而是**结构化卡片**：

| 消息类型 | 展示 | 数据来源 |
|:--|:--|:--|
| 用户消息 | 普通气泡 | user |
| 派单计划 | 卡片：角色清单（配方设计专家→安全性评估专家→法规合规专家） | `【任务分配】` |
| 专家结果 | 卡片：专家头像+角色名+结果文本+执行ID | delegate/确定性派单结果 |
| 招募通知 | 卡片：`【GitHub供给】`/`【招募】` 新员工加入 | 供给服务 |
| 失败提示 | 红色卡片：失败原因 | 子任务失败 |
| 汇总 | 高亮卡片：`【汇总】` 最终方案 | 聚合服务 |

**前端实现**：`GroupChatView` 根据 `content` 前缀识别消息类型，渲染对应卡片样式（后续可加 `msg_type` 字段）。

### 2. 任务状态与消息联动

```
任务群内消息流自动反映任务状态：
  创建任务 → 群创建 →【任务分配】→ 各专家结果 →【汇总】→ 任务 completed
  子任务失败 → 红色卡片 → 聚合仍完成（容错）→ 任务 completed
  聚合 LLM 全挂 →【汇总】拼接 → 任务 failed → 用户点「重新派单」
```

### 3. 群头部操作区（专业工作台）

- **状态徽标**：招募中 / 派单中 / 已完成 / 失败 / 已归档（颜色区分）；
- **成员数**：显示当前成员（Chief + 专家数）；
- **操作**：
  - 「追加专家」：从角色库/现有 Bot 加入群成员（已实现）；
  - 「重新派单」：失败任务一键重试（已实现）；
  - 「归档/恢复」：任务群归档（已实现）；
  - 「查看任务」：跳转任务中心详情。

### 4. 输入区增强

- `@` 定向：只显示**群成员 Bot**（含动态加入的临时专家），点击即 @；
- 引用：hover 消息可引用，输入区显示引用条（已实现）；
- 发送：未 @ 时触发自主派单（确定性引擎）；
- 派单中状态：按钮显示进度（"派单中…"），可继续输入（后端返回进行中提示）。

### 5. 成员管理（专业）

- 成员列表：Chief（管理员）+ 专家（含来源标记：系统/角色模板/GitHub 供给）；
- 添加：从可用 Bot 列表加入；
- 移除：非 Chief 成员可移除；
- 动态专家自动入群（P0-B 已实现）。

### 6. 专业视觉

- 遵循主题系统（`--color-primary/accent/border/...`）；
- 消息卡片圆角、头像、角色徽标；
- 汇总高亮卡片（渐变边框）；
- 失败红色提示条；
- 状态徽标颜色映射。

## 四、与现有能力的整合

| 能力 | 在专业群聊中的角色 |
|:--|:--|
| 确定性派单引擎 | 群内发言/任务创建后的执行核心（LLM 规划 + 确定性执行 + 聚合） |
| 角色模板库 | 「追加专家」与 L2 招募的数据源 |
| GitHub 供给 | 群聊内缺专家时实时创建"GitHub 来源专家"并自动入群 |
| MCP（github 等） | 专家执行子任务时调用外部能力（`mcp:github` 已可注册） |
| 任务状态机 | 群头部状态徽标 + 任务中心状态 |
| 异步轮询 | 群消息流自动刷新（检测【汇总】停止） |
| Redis 锁/限流 | 并发派单保护 |

## 五、分阶段实施计划

### 阶段 A：消息结构化展示（本次）
1. `GroupChatView` 消息类型识别（计划/结果/招募/失败/汇总卡片样式）；
2. 群头部状态徽标 + 成员数 +「查看任务」；
3. 输入区 @ 显示群成员（含动态专家）——已基本实现。

### 阶段 B：任务与群深度联动
4. `TaskGroup.plan` 持久化（建群计划复用，避免重复规划）；
5. 群头部显示任务状态变化（轮询任务状态更新徽标）；
6. 子任务结果依赖传递（前序结果拼入后续子任务 task 文本）。

### 阶段 C：体验增强
7. 重新派单批次标记（新消息加"第 N 次派单"标识）；
8. 【任务分配】展示子任务描述；
9. 群聊归档后只读。

---

## 六、验收标准

1. 群聊消息按类型结构化展示（计划/结果/招募/失败/汇总一眼可辨）；
2. 群头部展示任务状态、成员数，并支持追加专家/重新派单/归档；
3. 动态加入的专家在 @ 选择器、成员管理中可见；
4. 任务群中创建任务→自动配人→派单→结果→汇总全程可追溯；
5. 全部门禁通过（tsc/pytest/vitest）。
