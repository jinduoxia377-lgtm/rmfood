## 5. 「增强免疫」运行 · 发现间歇性前端崩溃（FAIL，P0）

- 同样的端到端操作（选「增强免疫」→ 点「生成配方」），后端 `/ai/generate` 仍返回 **200 且数据完整**：候选1 金银花5.8g/君、大枣5.8g/臣、灵芝5.7g/佐、甘草5.7g/佐；`efficacy_score=0.6006`、`overall_score=0.7465`、`safety_verdict.status=needs_attention`、含完整 `mechanism` 方解。
- **但前端渲染崩溃**，结果面板整体被 ErrorBoundary 错误卡片替换，**用户看不到任何候选配方**：
  - 控制台（7 条 error）：`TypeError: Cannot read properties of undefined (reading 'length')` at **`FormulaResultsPro.tsx:256`**；随后 `[ErrorBoundary] Caught error` / `[ErrorBoundary:component]` 接管。
  - 页面出现错误卡片文案：「⚠️ 页面出现问题 / 很抱歉，您当前访问的页面出现了一些问题。我们已记录此错误并会尽快修复。/ Cannot read properties of undefined (reading 'length') / 重试 / 刷新页面」。
- **根因（已定位到源码）**：`FormulaResultsPro.tsx` 的「知识库证据(RAG)」面板对 `ragEvidence.chunks.length`(:227)、`ragEvidence.whitelist.length`(:238)、`ragEvidence.blacklist.length`(:248) **无空值保护**。当后端返回的 `rag_evidence` 是**残缺对象**（truthy 但缺 `chunks`/`whitelist`/`blacklist` 数组）时即崩溃。类型 `RAGEvidence`（`types/ai.api.ts:31`）把这三个字段声明为**必填**，而 `api/ai.ts:978` 用 `as RAGEvidence | undefined` 强转绕过了运行时校验 → 类型安全缺口。
- **间歇性证据**：独立复跑「增强免疫」时，本次 top 候选 `rag_evidence` **缺失**（`hasRag:false`）→ 面板走「暂无知识库证据」分支，结果正常渲染（`RESULTS_CARDS_RENDERED=true`、无错误卡片）。故崩溃仅在「后端返回残缺 `rag_evidence`」时触发，**非必现，但真实存在**。

## 9. P0 崩溃修复与回归验证（2026-11-17 追加）

### 9.1 修复内容（两层防御）

**① API 运行时形状校验** —— `frontend/src/api/ai.ts`
- 新增 `normalizeRagEvidence(value: unknown): RAGEvidence | undefined`：
  - 非对象（null / 数组 / 标量）→ 返回 `undefined`，UI 走「暂无知识库证据」空态；
  - `chunks` / `whitelist` / `blacklist` 非数组 → 兜底 `[]`；
  - `enabled` 收敛 boolean、`query`/`summary` 收敛 string、`error` 保留 string 或 undefined。
- `normalizeGenerateResponse` 中把原先裸 `as RAGEvidence`（绕过运行时校验的根因）替换为
  `normalizeRagEvidence(data.rag_evidence)`。

**② 渲染层空值/类型防御** —— `FormulaResultsPro.tsx`
- 新增 `ragChunks` / `ragWhitelist` / `ragBlacklist`（`Array.isArray(...) ? ... : []`）；
- RAG 区所有 `.length` 与 `.map` 改用上述安全数组；
- 该区整体由既有 `ragEvidence ? (...)` 空值守卫包裹（其余 `query`/`enabled`/`summary` 访问均在守卫内）。
