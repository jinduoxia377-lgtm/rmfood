## 任务 1 — safety 三态明细展示（P1 观感）

### 问题
后端 `safety_verdict` 为三态 `{status: PASS/NEEDS_ATTENTION/REJECTED, is_compliant, violations[], warnings[]}`，经前端 `api/ai.ts deriveSafetyVerdict` 唯一推导为 `{status, source, reason, violations[], warnings[]}`。原 `CardHeader.tsx:59` 仅取 `reason(=violations[0] ?? warnings[0])` 作 badge tooltip，用户 hover 才见首条原因，无完整清单；且若后端把 `safety_passed` 改为区分「咨询级 warning」与「真越界」，前端无法正确渲染「is_compliant=true 但带 warnings」的情况，易被渲染成纯红标吓用户。

### 改动
- **新增** `frontend/src/components/ai/components/SafetyVerdictDetails.tsx`
  - 渲染 `safety_verdict` 完整明细的折叠面板。
  - 三态色板沿用 ADR-046 L5 约定：
    - `passed` → 绿（`success-*`）。关键：即使 `warnings[]` 非空，仍为绿底「合规通过」+ 单独黄标列出咨询级提示，**不渲染成红色**。
    - `needs_attention` → 黄（`warning-*`）容器；内部 `violations` 用红（`danger-*`）逐条列出，`warnings` 用黄（`warning-*`）逐条列出，两类明细视觉分离。
    - `unverified` → 灰虚线（`border-dashed` + `muted`），明示「未校验，不构成安全结论」。
  - 展开状态：有真违规时默认展开（即时可见原因），纯通过/未校验默认收起（避免刷屏）。
  - 全部文案走 i18n，无硬编码中文。
- **接线** `frontend/src/components/ai/NeuralResultCard.tsx`
  - 在 `CardHeader`（三态徽章）正下方插入 `<SafetyVerdictDetails verdict={candidate.safety_verdict} />`，与徽章同源 `deriveSafetyVerdict`，构成「徽章概览 + 明细面板」。

### i18n 新增键（`ai.formula.generateTab.*`，三语齐备）
` safetyVerdictDetailsTitle / safetyPassedHint / safetyPassedWithWarningsHint / safetyNeedsAttentionHint / safetyUnverifiedHint / safetyViolationsLabel / safetyWarningsLabel / formulaExplanationProse`

## 任务 2 — mechanism.explanation 方解散文展示（P2）

### 问题
`candidate.mechanism.explanation` 是后端现成的「方解与机理」散文（含具体药材 + 活性成分 + 靶点通路），但 `FormulaExplanationPanel.tsx` 仅用它做守卫判断（`mech.explanation || ...`），正文被丢弃，面板永远只渲染结构化 `mechanisms[]`/网络药理视图，方解散文从未呈现。

### 改动（`frontend/src/components/ai/features/GenerateTab/components/FormulaExplanationPanel.tsx`）
- 复用 `Interpretation` 类型新增 `explanation?: string` 字段。
- 适配层（`mech` → `adapted`）把原先硬置 `undefined` 的 `safety/usage/monitoring` 改为真实归一化：
  - `explanation: mech.explanation`（方解散文正文）。
  - `adaptSafety(mech.safety)` → `{food_homology_ratio, risk_level, notes[]}`。
  - `adaptUsage(mech.usage)` → `{form, dosage_summary, frequency, course, adjustment_hint}`。
  - `adaptMonitoring(mech.monitoring)` → `Array<{effect, metric, frequency}>`。
  - 三个 `adapt*` 均做空值/类型守卫，字段全空时返回 `undefined`（不渲染空容器）。
- 新增「方解与机理」小节，用仓库现有 pro 组件 `MarkdownRenderer`（零依赖）渲染 `explanation` 散文，位于「君臣佐使结构」之后、网络药理视图之前。
- 既有 `interp.safety` / `interp.usage` / `interp.monitoring` 渲染分支现因适配层填值而真正生效（用法/安全/监测三块）。
- `isInterpEmpty` 空态判定补入 `!interp.explanation`，避免「有散文却显示空容器」。

### i18n 新增键
`formulaExplanationProse`（「方解与机理」小节标题，三语齐备）。
