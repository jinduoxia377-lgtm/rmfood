## 6. 漂移 / 断裂 清单

### P0（阻断渲染 / 字段漂移致空白）
**无。** 未发现任何字段名漂移或链路断裂。候选卡片、方解/机理、safety_verdict、六维评分、RAG 证据均正确对齐后端实际返回。

### P1（功能性缺陷）
**无。**

### P2（数据未充分利用 / 体验小缺口）
1. **`mechanism.explanation` 主文本未直接展示** — `FormulaExplanationPanel.tsx:48-71` 用 `mech.explanation` 作为「有现成机理」的触发守卫（:49），但适配后的 `Interpretation` 未保留 explanation 字段，正文仅渲染 `constitution`(:139)/`mechanisms`(:146 网络图)/`synergy`(:172)/`disclaimer`(:208)。后端已产出的方解散文 `explanation` 被丢弃，机理以「网络药理图」形式呈现而非文字。同理 `mech.usage/safety/monitoring` 在 mechanism 优先分支被置 `undefined`（:61-63），仅回退 /ai/interpret 时才有。**非断裂**（mechanisms 图 + synergy 仍渲染），但浪费后端现成文字机理。
2. **`safety_verdict.violations/warnings` 明细无列表展示** — `deriveSafetyVerdict` 已把 violations/warnings 保留进 normalized verdict（api/ai.ts:824-829），`CardHeader.tsx:59` 仅取 `reason`（=violations[0]??warnings[0]）作徽章 tooltip。需关注/拒绝时用户 hover 才能看到首条原因，无完整 violations 清单 UI。**非断裂**（三态徽章正确），但明细触达弱。

## 7. 总结

配方生成链路**真实可用、字段全对齐、无幻想**。核心 hook → API 归一化 → store → 结果卡片/详情/机理/安全三态逐字段核对全部匹配后端权威返回；`normalizeGenerateResponse`/`normalizeGenerateCandidate` 正确把后端 `herb_combination`+`overall_score`+`safety_verdict` 映射为前端 `AICandidate`，并通过 `...(c)` spread 完整透传 `mechanism` 等未显式列出的字段，无丢字段。降级横幅、进度面板、缓存均真接线；2 处死代码（GenerationPanel.tsx、useGenerationHistory.ts）与 2 处 P2 数据利用不足（mechanism.explanation 正文、violations 明细列表）为可选优化项，不影响主功能正确性。
