## 1. P0：整页白屏崩溃（已修）

- 现象：任意宽度访问 `/landing`，`document.body.innerText.length === 0`、`#root` 子节点为 0、`sections=0`，控制台 `ReferenceError: process is not defined`。
- 根因：`frontend/src/config/ai.config.ts:75` 使用 `process.env?.NODE_ENV`。Vite 只静态替换字面量形式 `process.env.NODE_ENV`，**不替换可选链形式 `process.env?.NODE_ENV`**，导致浏览器端 `process` 未定义而在模块求值期抛错；该模块被主包急切引入，React 从未挂载。
- 修复：移除浏览器不兼容的 `process.env` 回退，仅保留 Vite 注入的 `import.meta.env?.VITE_APP_ENV || 'development'`。
- 影响面排查：全站另有 14 处 `process.env.NODE_ENV` 均为字面量形式（Vite 会替换），安全；仅此一处为可选链形式。
- 修复后：`bodyLen=2447`、`h1` 正常、`sections` 正常挂载、**0 error**。

## 2. 其余缺陷与修复（按文件所有权分组）

### 2.1 LaunchCountdown 顶部倒计时横幅（P0 视觉）
- 现象：320–414px 下左侧文案块固定 ~452px 无法收缩，徽章被推出左边缘、副标题/脚注被推出右边缘（`.truncate` 因祖先无宽度约束而失效）；768px 下"免费注册体验"CTA 右溢出（R=804 > vw=768）；320px 下右侧"倒计时单元+CTA"内在宽度 ~323px > 容器 286px。
- 修复（`sections/LaunchCountdown.tsx`）：
  - 外层行 L114 `+ sm:flex-wrap`（768px 可换行）；
  - 左块 L117 `+ w-full max-w-full sm:w-auto`（移动端给 `.truncate` 真实宽度边界，桌面 `sm:w-auto` 还原）；
  - 右组 L143 `flex … min-w-0 max-w-full` → `flex flex-wrap items-center justify-center …`（320px 下 CTA 换行到倒计时下方）。
- 复测：横幅宽度随视口收缩（286→446px），无溢出；副标题正确省略（`scrollW:390 / clientW:152, ellipsized:true`）；768px `flexWrap=wrap`（横幅 720px 不溢出）。

### 2.2 CTABanner 提交按钮无效类（Bug）
- 现象：`CTABanner.tsx:319` `className="w-full sm:w auto …"` —— `sm:w auto` 是无效 Tailwind（缺连字符），移动端按钮永不全宽。
- 修复：改为 `w-full sm:w-auto`（与同文件/Pricing 既有写法一致）。

### 2.3 Pricing 栅格断点不一致
- 现象：`Pricing.tsx:254` `grid-cols-1 md:grid-cols-3`（1→3 列跳变），与全站 `grid-cols-1 min-[480px]:grid-cols-2 lg:grid-cols-3` 规范不一致。
- 修复：统一为 `grid-cols-1 min-[480px]:grid-cols-2 lg:grid-cols-3`。
- 复测：1 列(320–414) → 2 列(480/768) → 3 列(1024)。

### 2.4 PainPoints 480px 边际溢出
- 现象：仅 480–483px 窄带内 `<section id="pain-points">` `scrollWidth=483 > 480`（+3px）。
- 根因：某卡转折句中不可断的拉丁串 `INFO/WARN/CRITICAL）`，默认 `word-break:normal` 下最小内容宽 193.5px 超出两列轨道（149px 可用）。
- 修复（`sections/PainPoints.tsx:70`）：转折句 `<p>` 加 `[overflow-wrap:anywhere]`，允许该串断行；对中文无影响。
- 复测：480px 与 483px 均 `ovf:false`。

### 2.5 Algorithms 性能基准表横向溢出
- 现象：320/360px 下 5 列基准表（操作类型/P50/P95/P99/SLA目标）撑破卡片（表 R=372 > vw=320）。
- 根因：包裹层 `overflow-x-auto`（L189）**缺少宽度上界**，包裹层被表格内在宽度撑大而非在卡内滚动。
- 修复：包裹层加 `max-w-full`。
- 复测：包裹层 17→303（284px）、`scrollW:354, scrolls:true, withinCard:true`，页面不溢出。

### 2.6 UseCases "核心指标"表横向溢出
- 现象：480/483px 两列卡内"活性肽库…"表撑破（表 R=489 > vw=480），该表**完全没有滚动包裹层**。
- 修复（`sections/UseCases.tsx:103`）：表格外包一层 `<div className="overflow-x-auto max-w-full">`。
- 复测：包裹层 275→438（163px）、`scrollW:214, scrolls:true, withinCard:true`，页面不溢出。

## 3. 规范沉淀（落地页移动端约定）

1. 断点分带沿用全站规范：手机 320–479=1 列 / 平板手机 480–1023=2 列 / 平板 1024–1279=3 列 / 桌面≥1280=4 列；栅格统一 `grid-cols-1 min-[480px]:grid-cols-2 lg:grid-cols-3 [xl:grid-cols-4]`。**勿用 `md:grid-cols-3` 跳变**（Pricing 已纠）。
2. 触屏热区：交互目标 `min-h/min-w 44px`（本次保留并复核倒计时 CTA、导航、页脚链接）。
3. 需要截断的单行文案：`.truncate` 生效的前提是**祖先链有确定的宽度边界**；flex 子项须带 `min-w-0`，必要时补 `max-w-full`，否则截断失效并横向溢出（LaunchCountdown 即此根因）。
4. 宽表格：包裹层必须 `overflow-x-auto max-w-full` 二者兼备——只有 `overflow-x-auto` 而无宽度上界时，包裹层会被内容撑大、失去滚动意义（Algorithms/UseCases 均此根因）。
5. 横幅/工具条类"多元素并排"容器：移动端内在宽度可能超视口，需 `flex-wrap` 让超宽时降级换行，而非依赖 `shrink`（倒计时右组即此）。
6. 严禁在浏览器代码中使用 `process.env` 的**可选链/非常量形式**；环境变量统一走 `import.meta.env`。
