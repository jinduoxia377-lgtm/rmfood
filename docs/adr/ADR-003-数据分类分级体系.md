# ADR-003: 数据分类分级与安全管控体系

## 状态
✅ 已接受 (2026-06-05)

## 上下文

RMFOOD 平台涉及多种数据类型，包括：核心配方、实验数据、客户信息、供应商数据等。当前缺乏正式的数据分类体系，所有数据采用统一的安全策略，存在以下风险：
1. 核心配方与公开数据同等防护，泄露风险高
2. 无数据分级访问控制，内部人员可接触敏感数据
3. 缺乏数据生命周期管理（归档、保留、销毁）
4. 食品行业特有的合规要求（注册申报数据需按法规保留）

## 决策

采用 **四层数据分类模型**，结合 **食品行业特有数据类型**：

| 等级 | 标签 | 示例 | 加密要求 | 访问控制 | 审计要求 |
|:-----|:-----|:-----|:---------|:---------|:---------|
| **L4 绝密** | `classification:top-secret` | 完整配方表+工艺参数 | AES-256 存储加密 | 指定人员 + 动态水印 | 全量审计 |
| **L3 机密** | `classification:secret` | 实验原始数据、客户需求 | AES-256 存储加密 | 角色隔离 + 脱敏展示 | 季度审计 |
| **L2 内部** | `classification:internal` | 供应商信息、内部报告 | TLS 传输加密 | 普通访问控制 | 年度审查 |
| **L1 公开** | `classification:public` | 宣传资料、已发表论文 | 基本防护 | 公开可访问 | 无需审计 |

### 数据标记方案

所有数据模型增加分类标记字段：

```python
from enum import Enum, auto

class DataClassification(Enum):
    PUBLIC = auto()       # L1
    INTERNAL = auto()     # L2
    SECRET = auto()       # L3
    TOP_SECRET = auto()   # L4

# 混入基类，应用于需要分类的 ORM 模型
class ClassifiedMixin:
    data_classification = Column(
        Enum(DataClassification),
        default=DataClassification.INTERNAL,
        nullable=False
    )
    data_retention_days = Column(Integer, nullable=True)
    data_owner = Column(String(100), nullable=True)
```

### 数据生命周期策略

| 分类 | 在线保留 | 归档 | 销毁 |
|:-----|:---------|:-----|:-----|
| L4 绝密 | 永久（活跃期间） | 项目结束后 5 年 | 客户书面确认 |
| L3 机密 | 项目期间 + 3 年 | +5 年 | 客户书面确认 |
| L2 内部 | 项目期间 + 1 年 | +3 年 | 自动清理 |
| L1 公开 | 永久 | 无需 | 按业务需求 |

## 后果

### 正面
- 敏感数据（核心配方）获得最高级别保护
- 合规审计可证明数据管控符合要求
- 数据保留策略满足 GB/T 法规要求

### 负面
- 需要对所有现有数据模型添加分类标记（增量工作量）
- L4 数据的水印和审计会增加系统开销
- 团队需要培训数据分类规范
