# ADR-012: 智能对话架构融合 — DeepSeek Harness 模式应用

**状态**: 已实施  
**日期**: 2026-08-23  
**决策者**: RMFOOD AI Team

---

## 1. 上下文

RMFOOD 智能对话模块（`frontend/src/components/ai/features/`）经过深度测试发现以下核心问题：

- **数据不一致**：localStorage + IndexedDB + 后端 API 三层存储独立运行，切换会话后刷新页面消息丢失
- **上下文截断**：硬编码 `slice(-10).map(m => content.slice(0, 1000))` 破坏长对话连贯性
- **竞态条件**：思考步骤加载使用 `prevMsgCountRef` 在 effect 内更新，并发消息时读取到错误值
- **类型不安全**：`eventBus.emit('thinking:step' as any, ...)` 等135处 `as any` 绕过类型检查
- **虚拟滚动错位**：固定 `estimateSize: () => 140` 导致长消息滚动跳动

参照 DeepSeek Harness 架构文档（`docs/deepseek-harness-analysis/`），提取其核心设计模式进行融合。

---

## 2. 决策

### 2.1 引入统一存储能力层（ChatStorageCapability）

**问题**：散乱的 localStorage key（`chat_messages`、`rmfood_chat_sessions_v1`、`chat_session_msgs_{id}`）与 IndexedDB（`rmfood_chat_history_v2`）两套独立存储。

**方案**：建立 `ChatStorageService` 作为唯一写入点，采用 IndexedDB 主存储 + localStorage 缓存 + 后端同步三层架构。

```
写入路径: useChatMessages → ChatStorageService.saveMessages(sessionId, messages)
          → IndexedDB (primary) + localStorage cache (TTL 5min)
读取路径: useChatCallbacks.handleSelectSession
          → ChatStorageService.loadMessages(sessionId)
          → 本地缓存 → IndexedDB → 降级: localStorage 旧格式 → 后端API
```

### 2.2 Token 预算管理替代硬截断

**问题**：`useChatMessages.ts:191` 强制每条消息截断1000字，多轮配方设计对话上下文严重不足。

**方案**：引入 `TokenBudgetManager`，基于中文/英文/数字混合权重估算 token，按预算窗口选择历史消息，保留首条用户消息 + 最近 N 条完整上下文。

```typescript
// 估算模型
cnChar * 1.5 + enWord * 0.8 + num * 1.2 + newline * 0.3

// 选择策略：从最新消息向前累加，直至 token 预算耗尽
// 始终保留第一条用户消息（对话起点）
// 保证最少保留 4 条消息
```

### 2.3 EventBus 类型安全改造

**问题**：135处 `as any` 绕过 TypeScript 类型检查，事件名拼写错误无法在编译期捕获。

**方案**：扩展 `EventPayloadMap` 新增 `context:updated` 和 `context:cleared` 事件定义，修复所有 `as any` 调用。

### 2.4 思考步骤竞态修复

**问题**：`ChatTab.tsx` 中 `prevMsgCountRef` 在 effect 内部更新，并发消息时可能重复处理或跳过。

**方案**：改为使用稳定的 `lastProcessedMsgCountRef`，在 effect 开始前消费当前计数，避免 re-entrancy 问题。

### 2.5 虚拟滚动动态高度估计

**问题**：固定 140px 估计值无法适应差异巨大的 AI 回复长度。

**方案**：实现 `getEstimatedSize(index)` 动态函数，根据消息角色和内容长度计算估计高度。

## 3. 架构变化

```
修改前                                    修改后
─────────────────────────────────────────────────────────────
localStorage chat_messages                IndexedDB (ChatStorageService)
localStorage rmfood_chat_sessions_v1      IndexedDB + localStorage 缓存
localStorage chat_session_msgs_{id}       删除，统一到 ChatStorageService
硬截断 1000字/条                          TokenBudgetManager 智能选择
eventBus emit('xxx' as any)               eventBus emit('xxx', typedPayload)
fixed estimateSize=140                    dynamic getEstimatedSize(index)
```

## 6. 后果

### 正向影响
- ✅ 会话切换后刷新页面消息不再丢失
- ✅ 长对话上下文完整传递给后端（不再截断）
- ✅ TypeScript 类型安全改进，编译时可捕获更多错误
- ✅ 虚拟滚动不再因高度估计不准导致跳动
- ✅ 为后续 Compaction/Fork/Waterfall 能力打下基础
- ✅ 子智能体委托支持复杂配方多步骤处理
- ✅ 斜杠指令支持 /clear /compact /topic /fork /resume /help
- ✅ 会话列表支持 hover 创建分支

### 风险
- ⚠️ IndexedDB 初始化有延迟，首次加载可能略慢（已加 loading 状态）
- ⚠️ 旧 localStorage 数据需要迁移（已实现兼容读取）
- ⚠️ `useChatCallbacks` 中 `handleNewSession`/`handleSelectSession` 变为 async，调用方需 await

### 向后兼容
- ✅ `useChatMessages` 接口完全不变
- ✅ `ChatMessage` 类型不变
- ✅ 旧 localStorage 数据自动迁移到 IndexedDB
