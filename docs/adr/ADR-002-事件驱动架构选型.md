# ADR-002: 事件驱动架构选型与实施策略

## 状态
✅ 已接受 (2026-06-05)

## 上下文

当前系统使用 CDC（Change Data Capture）监听器提供基础的变更捕获能力。随着功能扩展，出现以下需求：
1. **配方审核通过后** → 自动触发备案材料生成 + 通知团队成员
2. **实验数据更新后** → 自动更新配方稳定性评估
3. **合规检查违规时** → 实时推送告警给合规团队
4. Webhook 第三方回调需要可靠的事件投递保障

当前 CDC 监听器缺乏：**事件路由、持久化、重放、死信处理**等企业级特性。

## 决策

### 第一阶段（0-3个月）：Redis Streams 轻量起步
- 使用 Redis Streams 作为事件总线
- 利用 Redis 7 内置的消费者组机制
- 适合事务性消息场景，无需额外基础设施

### 第二阶段（3-6个月）：迁移至 RabbitMQ
- 从 Redis Streams 迁移至 RabbitMQ，适配器模式确保业务代码不变
- RabbitMQ 提供更完善的消息确认、死信队列、延迟消息
- 在 Adapter 层封装，上层业务代码零感知

### 事件分类策略

| 事件类型 | 持久化要求 | 投递保障 | 示例 |
|:---------|:----------:|:---------|:-----|
| **领域事件** | 是 | 至少一次 | `FormulaCreated`, `ExperimentCompleted` |
| **通知事件** | 否 | 尽力投递 | `UserMentioned`, `TaskAssigned` |
| **数据同步事件** | 是 | 精确一次 | `FormulaUpdated`, `IngredientChanged` |
| **审计事件** | 是 | 至少一次 | `UserLoggedIn`, `DataExported` |

### 事件命名规范
- 过去分词命名：`FormulaCreated`, `ExperimentApproved`
- 包含版本前缀：`v1.FormulaCreated`
- 事件 Schema 存储在 `schemas/events/` 目录

## 后果

### 正面
- 模块间解耦：配方模块无需直接调用实验模块
- 异步处理提升响应速度：合规检查可后台执行
- 事件存储支持审计追溯、时间旅行调试
- 为 CQRS 和 Event Sourcing 奠定基础

### 负面
- 分布式事务复杂性：涉及跨模块一致性需要 Saga 模式
- 调试难度增加：异步流追踪需要分布式追踪工具
- 初期需要额外基础设施维护
