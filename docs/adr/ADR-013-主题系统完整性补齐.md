# ADR-013 — 主题系统完整性补齐

**状态**：✅ 已接受  
**日期**：2026-08-15  
**领域**：前端 / UI/UX  
**上下文**：[ADR-012](./ADR-012-主题系统精简与统一.md)

---

## 背景

ADR-012 完成了主题系统的架构收敛（单一状态源、语义变量、类型统一），但落地时仍存在三类完整性的缺口：

1. **Token 覆盖不完整**：`dark.css` 缺少语义色 light/dark 变体、中性色全阶、补充色系（orange/purple/cyan 等），导致图表多系列配色无法动态响应主题切换。
2. **语义化工具类不足**：`index.css` 虽定义了 `.text-text-primary` 等类，但缺少阴影、圆角、表面层的系统化语义类，组件被迫使用 `bg-white dark:bg-neutral-900` 双值写法或硬编码 `var(--xxx)`。
3. **JS/TS 颜色访问缺口**：图表引擎（Recharts）和 Canvas 需要程序化获取当前主题色，但 `SemanticColors` 仅用于 CSS 变量生成，没有 JS 侧的统一入口。
4. **布局层硬编码**：`MainLayout.tsx` 汉堡菜单等按钮仍用 Tailwind 默认色（`bg-neutral-100`），与主题系统割裂。
5. **主题切换过渡无遮罩**：`.theme-transition-overlay` 类已定义但未在任何组件中使用，切换时缺乏 Apple Spring 风格的淡入淡出遮罩。

## 决策

本次补齐涵盖五层，自上而下：

### 1. `dark.css` — 补全语义 token

| 新增类别 | 变量示例 |
|:--------:|:--------:|
| 品牌色全阶 | `--color-primary-50` … `--color-primary-900` |
| 功能色 light 变体 | `--color-success-light`、`--color-warning-light`、`--color-error-light`、`--color-info-light` |
| 功能色语义容器 | `--color-success-50`（暗底深色）、`--color-success-400`（亮色）等 |
| 中性色全阶（暗） | `--color-neutral-50` … `--color-neutral-900`（暗色 Slate 系） |
| 补充色系 | `--color-orange-500/600`、`--color-purple-500/600`、`--color-pink-500/600` 等 14 组 |
| 背景/表面别名 | `--bg-surface`、`--bg-surface-hover`、`--border-default`、`--border-divider` |
| 渐变文字暗色 | `--gradient-trend-up`（绿色调）、`--gradient-trend-down`（红色调） |

### 2. `base.css` — 补充基础 token

- 补充补充色系（`orange`、`cyan`、`pink`、`sky`、`indigo`、`teal`、`lime`、`yellow`）
- 添加边框语义别名 `--border-default`、`--border-divider`
- 添加 `--header-height` 布局变量

### 3. `@theme` 块（`index.css`）— 扩展 Shadow/Borders/Surfaces

新增 Tailwind v4 可直接引用的 Token：

```css
--shadow-sm, --shadow-md, --shadow-lg, --shadow-xl, --shadow-card, --shadow-modal, ...
--border-default, --border-divider
--surface-default, --surface-variant, --surface-elevated, --surface-hover
```

### 4. `semantic-utils.css` — 新建语义工具类

提供可直接在 TSX 中使用的组件级语义类：

```css
/* 品牌/功能色 */
.text-primary-main  .text-success-main  .text-warning-main  .text-error-main
.bg-primary-container .bg-success-container .bg-error-container

/* 中性色 */
.bg-neutral-default  .bg-neutral-subtle  .text-neutral-muted

/* 表面层 */
.surface-card  .surface-elevated  .surface-glass  .surface-overlay
.divider-horizontal  .divider-vertical

/* 骨架屏 */
.skeleton-base

/* 焦点环 */
.focus-ring

/* 无障碍/阅读模式 */
[data-a11y-mode="high-contrast"] / [data-reading-mode="sepia"]
```

### 5. `useSemanticTheme` hook — JS/TS 语义色访问

新文件 `hooks/useSemanticTheme.tsx`，导出：

- `useSemanticTheme()` → 返回 `SemanticColorVars` 接口，所有值均为 `var(--xxx)` CSS 字符串
- `getSemanticColor(name)` → 通过 `getComputedStyle` 读取实际渲染的 hex 值，供 Canvas/Recharts 使用

集成到 `@/theme` 模块导出，与 `useIsDarkMode`、`useTheme` 同级。

### 6. `MainLayout.tsx` — 布局层语义化

- 替换 `hover:bg-neutral-100 dark:hover:bg-neutral-800` → `hover:bg-background-hover`
- 替换 `bg-primary-50 dark:bg-primary-900/20` → `bg-primary-container`
- 替换 `focus:ring-primary-500` → `focus:ring-primary-main`
- 引入 `useTheme()` 获取 `isTransitioning`，挂载 `.theme-transition-overlay` 遮罩层

### 7. `@/theme/index.ts` — 统一导出

新增 `useSemanticTheme`、`getSemanticColor`、`SemanticColorVars` 三个符号。

## 后果

### 正向收益

| 维度 | 改善 |
|:-----|:----:|
| 主题覆盖度 | 全量功能色两态覆盖，图表多系列自动响应 |
| 组件一致性 | `surface-card` 等语义类替代手动 `bg-white dark:bg-neutral-900 border rounded shadow` |
| JS 色彩访问 | `getSemanticColor('primary')` 可在 chart/engine 代码中获取实时色值 |
| 过渡体验 | 切换主题时播放 200ms fade overlay，符合 Apple Spring 规范 |
| 无障碍 | `[data-a11y-mode]` 选择器支持全局高对比度覆盖 |

### 已知限制

- **中性色替换未全量推进**：整个项目约 7,469 处 `bg-neutral-*` / `text-neutral-*` 硬编码仍存在于各业务组件。本次仅修复了最核心的 `MainLayout.tsx`（布局骨架）。逐组件推进需单独迭代，风险与收益比需评估。
- **`semantic-utils.css` 与 Tailwind 类共存**：新语义类是补充而非替代，不会破坏现有用法。
- **`getSemanticColor()` 的 computeStyle 开销**：在 React render 路径中调用频率低（主要用于初始化图表配置），不会成为性能瓶颈。
