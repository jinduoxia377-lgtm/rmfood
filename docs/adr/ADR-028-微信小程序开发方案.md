## 一、背景与目标

### 1.1 现状分析

RMFOOD 当前拥有完整的前后端架构：

| 层次 | 技术栈 | 规模 |
|------|--------|------|
| 前端 Web | React 19 + TypeScript + Vite 8 + TailwindCSS 4 | 923+ TSX/TS 文件，26+ 页面 |
| 后端 API | FastAPI + PostgreSQL + Redis | 50+ 路由模块，RESTful + WebSocket |
| AI 引擎 | 多模型接入 + 配方优化算法 | 多目标优化、RAG、知识图谱 |
| 移动端适配 | 已有 `/api/v1/mobile/*` 精简路由 | 仅仪表盘、同步、通知、溯源、审批 |

### 1.2 目标

构建一个**专业级微信小程序**，面向最终用户（B端研究员/C端消费者），提供：
- AI 驱动的药食同源配方设计与咨询
- 配方浏览、收藏、搜索
- 个人健康管理入口

### 1.3 非目标

- **不迁移现有 Web 前端代码**（React/Vite/Tailwind 体系无法直接运行在小程序环境）
- **不修改现有后端 API 架构**（复用现有 FastAPI 接口）
- **不做原生 APP**（小程序优先，后续评估 Taro 多端输出）

- Taro 的 `<View>` / `<Text>` 标签映射语义与 Web 组件对齐

## 三、API 对接方案

### 3.1 认证策略调整

**现状问题**：Web 端使用 HttpOnly Cookie 认证，小程序无法直接读写 Cookie。

**解决方案**：新增微信授权登录接口，Token 存储于小程序本地。

```
后端新增接口:
  POST /api/v1/auth/wechat-login
  Body: { code: string }  // wx.login() 获取的临时码
  Response: { access_token, refresh_token, user: User }

前端存储:
  wx.setStorageSync('access_token', token)
  wx.setStorageSync('refresh_token', token)

请求头注入:
  Authorization: Bearer ${token}
```

### 3.2 后端需新增的移动端 API

| 序号 | 接口路径 | 方法 | 说明 |
|------|---------|------|------|
| 1 | `/api/v1/auth/wechat-login` | POST | 微信授权登录 |
| 2 | `/api/v1/auth/wechat-refresh` | POST | 刷新 Token |
| 3 | `/api/v1/mobile/formulas` | GET | 配方列表（精简字段） |
| 4 | `/api/v1/mobile/formulas/{id}` | GET | 配方详情（精简字段） |
| 5 | `/api/v1/mobile/chat/sessions` | GET | 会话列表 |
| 6 | `/api/v1/mobile/chat/sessions` | POST | 创建会话 |
| 7 | `/api/v1/mobile/chat/messages` | POST | 发送消息 |
| 8 | `/api/v1/mobile/chat/messages/stream` | POST | AI 回复流式输出 |
| 9 | `/api/v1/mobile/formulas/favorite` | POST | 收藏/取消收藏 |
| 10 | `/api/v1/mobile/health/check` | POST | 体质诊断问卷提交 |

### 3.3 现有后端 API 直接复用

以下接口无需修改，小程序直接调用：

| 模块 | 路径前缀 | 用途 |
|------|---------|------|
| 配方 | `/api/v1/formulas/*` | 配方 CRUD（需精简返回字段） |
| 对话 | `/api/v1/chat/*` | 会话管理 |
| AI 生成 | `/api/v1/ai/generate/*` | 配方生成 |
| 搜索 | `/api/v1/search/*` | 成分搜索 |
| 知识图谱 | `/api/v1/kg/*` | 成分关联分析 |
| 通知 | `/api/v1/notifications/*` | 消息推送 |
| 移动端 | `/api/v1/mobile/*` | 已有路由，可扩展 |

### 3.4 流式响应方案

**关键约束**：小程序 WebSocket 有域名限制且需备案，不推荐用于 AI 流式输出。

**推荐方案**：SSE（Server-Sent Events）

```
后端新增:
  POST /api/v1/ai/chat/stream
  Content-Type: text/event-stream
  响应格式:
    data: {"type": "chunk", "content": "这部分是..."}
    data: {"type": "finish", "content": "完整回复", "session_id": 123}

前端消费:
  const eventSource = new Taro.RealtimeChannel('xxx')  // 或使用自定义 TCP
  // Taro 4.x 支持 fetch，可创建 EventSource-like 实现
```

若后端暂时不支持 SSE，可采用**轮询延迟策略**作为降级方案：
- 首次请求获取 `task_id`
- 轮询 `/api/v1/ai/task/{task_id}` 获取进度
- 完成后返回完整结果

#### 4.2.3 个人中心（profile）
- 用户头像 + 昵称（微信授权信息）

## 六、数据缓存策略

参考用户偏好：**「缓存功能实施优先级」**，按以下策略实施：

### 6.1 缓存层级

| 层级 | 存储方式 | TTL | 适用场景 |
|------|---------|-----|---------|
| 内存缓存 | Zustand Store | 会话级 | 当前页面数据 |
| 本地存储 | wx.setStorage | 24h | 已查看配方、会话列表 |
| 离线缓存 | 小程序分包 + 预加载 | 永久 | 静态资源、模板 |

### 6.2 缓存实现

```typescript
// src/utils/cache.ts
const CACHE_KEYS = {
  formulas: 'rmfood_formulas_cache',
  sessions: 'rmfood_sessions_cache',
  user: 'rmfood_user_cache',
} as const

const CACHE_TTL = 24 * 60 * 60 * 1000 // 24小时

export function setCache<T>(key: string, data: T): void {
  wx.setStorageSync(key, {
    data,
    timestamp: Date.now(),
  })
}

export function getCache<T>(key: string): T | null {
  const item = wx.getStorageSync(key)
  if (!item) return null
  if (Date.now() - item.timestamp > CACHE_TTL) {
    wx.removeStorageSync(key)
    return null
  }
  return item.data as T
}
```

### 6.3 预加载策略

```typescript
// 首页加载时预加载热门配方
useEffect(() => {
  const cached = getCache<Formulas[]>('formulas_hot_cache')
  if (cached) {
    setHotFormulas(cached) // 直接渲染缓存数据
  }
  fetchHotFormulas().then(data => {
    setCache('formulas_hot_cache', data)
    setHotFormulas(data)
  })
}, [])
```

## 九、风险评估与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 小程序 WebSocket 域名限制 | AI 流式输出受限 | 采用 SSE 或轮询方案 |
| 后端 WeChat 登录接口缺失 | 认证无法打通 | Phase 1 优先补全 |
| 配方详情 Markdown 渲染性能 | 长内容加载慢 | 分页渲染 + 虚拟列表 |
| 包体积超 2MB | 无法发布 | 分包 + 图片压缩 + 第三方库按需引入 |
| AI 响应延迟 | 用户体验差 | 流式输出 + Loading 骨架屏 |
| 微信审核拒审 | 无法上线 | 提前了解审核规范，避免敏感词 |
