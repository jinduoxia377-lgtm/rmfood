# ADR-015 — 主题系统完整性审计与修复

**状态**：✅ 已接受  
**日期**：2026-08-15  
**领域**：前端 / UI/UX

---

## 背景

ADR-012 统一了主题架构，ADR-013 补全了设计 Token，ADR-014 完成了组件级批量迁移（928 文件、263,039 次替换）。本审计为终验，确认主题系统无遗漏、无断裂。

## 发现的缺陷与修复

### 缺陷 1：`semantic-utils.css` 未导入

- **现象**：迁移脚本已将大量组件中的 `bg-white dark:bg-neutral-900` 替换为 `surface-card`，但 `semantic-utils.css` 从未被 `index.css` 导入，导致所有语义工具类（`.surface-card`、`.bg-neutral-*` 50–900、`.text-neutral-*`、`.border-neutral-*`、骨架屏、无障碍模式）全部失效。
- **修复**：在 `index.css` 第 34 行添加 `@import './styles/components/semantic-utils.css';`

### 缺陷 2：`dark.css` 缺少中性色暗色覆盖

- **现象**：base.css 定义了 `--color-neutral-50`（#F9FAFB）到 `--color-neutral-900`（#111827）共 10 级亮色中性变量，但 dark.css 未做任何覆盖。暗色模式下 `bg-neutral-50` 等类仍使用亮色，文字不可读。
- **修复**：在 dark.css 的文本变量后插入中性色暗色覆盖块，采用 Apple HIG 分层灰度（#1C1C1E → #F2F2F7），与暗色表面层对齐。

### 缺陷 3：`useSemanticTheme` 未从 `@/theme` 导出

- **现象**：`hooks/useSemanticTheme.tsx` 存在且功能完整，但未在 `theme/index.ts` 中导出，导致图表、画布等需要程序化颜色访问的组件无法使用。
- **修复**：在 `theme/index.ts` 添加 `export { useSemanticTheme, getSemanticColor }` 和 `export type { SemanticColorVars }`。

## 类型定义

`types/theme.types.ts` 导出：

| 类型 | 说明 |
|:-----|:-----|
| `ThemeMode` | `'light' \| 'dark' \| 'system'` |
| `AccessibilityMode` | `'normal' \| 'high-contrast' \| 'reading' \| 'color-blind'` |
| `TransitionType` | `'fade' \| 'slide' \| 'scale' \| 'none'` |
| `PresetThemeId` | `'light-default' \| 'dark-default'` |
| `SemanticColors` | 品牌/成功/警告/危险/信息/中性 完整语义色映射 |
| `Typography` / `Spacing` / `Shadows` / `Breakpoints` | 设计 Token 数据模型 |
