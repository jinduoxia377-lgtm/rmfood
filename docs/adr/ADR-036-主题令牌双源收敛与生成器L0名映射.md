# ADR-036: 主题令牌双源收敛与生成器 L0 名映射

> **状态**：✅ 已接受　**日期**：2026-10-02　**领域**：前端/UI/UX（主题系统）
> **关联**：M2 T-B1/T-B2a/T-B2b、规范 v1.1.5/v1.1.8、缺陷 D-2/D-3、决策 T-B2b

## 背景

主题系统曾存在**两套令牌真相源**：

1. **L0 静态源**：`base.css`/`dark.css` 的 `:root`/`.dark` 块（`--color-primary` 等），
   被 CSS 消费者（`var(--color-primary)`、Tailwind 工具类）读取。
2. **L1 注入源**：`theme.presets.ts` 的 `generateCSSVariables()` 生成的内联
   自定义属性（写入 `<html>`），此前品牌色映射到 `--color-primary-main`
   （值 `#34C759` Apple 绿，**非**品牌色 `#10B981`）。

两者**同义不同值**（`--color-primary` = `#10B981` vs `--color-primary-main` = `#34C759`），
导致 32 处冲突，且**自定义主题 / 无障碍变体 / 文件导入对品牌色完全无效**
（注入写 `--color-primary-main`，但 CSS 消费者读 `--color-primary`）。

## 决策

1. **T-B1 双源收敛**：`preset-align.mjs` 逐令牌对齐 L0 与 L1，同义不同值 32 → 0；
   品牌主色统一为 `#10B981`（亮）/ `#34d399`（暗），作废 Apple 绿 `#34C759`。
2. **T-B2a 生成器改 L0 名**：`generateCSSVariables` 的 `COLOR_MAIN_TO_L0` 映射表
   把 `colors.primary.main` 等写 L0 名（`--color-primary`），而非 `-main` 后缀名。
   安全性来自 T-B1 先行对齐（对齐后改名对内置预设是零视觉变化）。
3. **T-B2b 纯净预设跳过注入**：`isCleanBuiltinPreset()` 判定内置纯净预设
   （`light-default`/`dark-default` 且 `colors` 未被无障碍变体修改）时
   `applyThemeToDOM` **跳过内联注入**（`<html>` 内联自定义属性 86 → 0），
   L0 由 `base.css`/`dark.css` 静态提供；仅自定义主题 / 导入主题 / 无障碍变体
   注入差异部分。

## 后果

- **正面**：自定义主题 / 无障碍变体对品牌色生效；`<html>` 内联 0（性能 + 可预测性）；
  双源冲突归零。
- **负面 / 约束**：无障碍变体仍注入全量令牌（93 个，部分对 L0 冗余），
  精确差异注入记 M3/M4 优化项（需逐令牌比对 L0 计算值）。
- **不变量**：`@theme` 106 条自引用登记声明**不得删除**（Tailwind 工具类生成机制，
  v1.1.7 勘误证伪 `@theme inline` 方案）。

## 备选方案（已否决）

- **改用 `@theme inline` 根治自引用**（v1.1.6 曾建议）：实测导致 Tailwind 无法生成
  带 opacity 修饰符的类（`ring-primary-600/40` 等 0 生成），已否决（v1.1.7 勘误）。
- **删除 `@theme` 106 条登记**：会导致全项目 `bg-<族>-<档>` 工具类不生成，否决。
