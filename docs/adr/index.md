## ADR 编写指南

### 什么时候需要写 ADR
- 引入新的架构模式或技术栈
- 改变现有架构的重大决策
- 数据模型、API 协议的重大变更
- 外部服务/工具的选型决策

### ADR 生命周期
```
提案 → 评审 → 已接受 / 已否决 → (可选) 已废弃 / 已替换
```

### 编写原则
- **及时**：决策做出后立即记录
- **简洁**：一个决策一个 ADR
- **上下文优先**：背景和动机比方案更持久
- **保留选项**：记录考虑过的其他方案和否决原因
