# ADR-030: 配方在线验证工作流架构设计

## 状态
✅ 已接受 | 2026-09-22

## 上下文

**问题陈述：**
现有"配方管理"页面中已生成的配方，缺乏系统化的在线验证机制。当前流程需要人工多次干预（逐个调用安全性检查、兼容性检测、功效预测等），效率低下且易遗漏。实验管理模块虽有实验记录功能，但与配方验证流程之间缺乏自动化联动。

**目标：**
1. 从配方管理页面一键触发全流程验证，无需人工多次干预
2. 在实验管理模块实现验证工作流的可视化跟踪
3. 自动对比预测值与实验实测值，评估配方科学性和合理性
4. 建立完整的验证报告体系，支持迭代优化

### 验证阶段定义

| 阶段 | task_type | 权重 | 核心能力 |
|:-----|:----------|:----:|:---------|
| 安全性检查 | `safety_check` | 25% | GB 16740/ADI/UL 阈值比对，三级预警（INFO/WARNING/CRITICAL） |
| 兼容性检测 | `compatibility_check` | 20% | 4层架构：化学/药理学/营养学/法规层面相互作用分析 |
| 功效预测 | `efficacy_prediction` | 20% | PopPK/PD 一室模型模拟，Tmax/Cmax/AUC/效应窗口 |
| 稳定性预测 | `stability_prediction` | 15% | 货架期估算，降解速率，关键降解路径 |
| 风味评分 | `taste_prediction` | 10% | 甜度/苦味/酸味/鲜味多维感官预测 |
| 协同效应分析 | `synergy_analysis` | 10% | 网络药理学 Synergy Index (SI) 计算 |
| 数据对比 | `data_comparison` | 10% | 预测值与实验实测值偏差分析（需关联实验） |

### 加权综合评分公式

```
overall_score = Σ(stage_score × stage_weight)
```

### 结论判定规则

| 条件 | 结论 |
|:-----|:-----|
| 安全或兼容阶段未通过 | ❌ 未通过 (FAILED) |
| ≥2 个阶段未通过 | ⚡ 有条件通过 (CONDITIONAL) |
| overall_score ≥ 70 且仅 ≤1 个阶段未通过 | ✅ 通过 (PASSED) |
| 其他 | 待验证 (INCONCLUSIVE) |

### API 端点设计

```
POST   /api/v1/formulas/{formula_id}/validate          # 一键触发验证
GET    /api/v1/formulas/{formula_id}/validation/{id}   # 查询进度
GET    /api/v1/formulas/{formula_id}/validation        # 历史验证记录
POST   /api/v1/formulas/{formula_id}/validation/{id}/retry  # 重试失败阶段
```

### WebSocket 消息类型

新增 `MessageType.VALIDATION_PROGRESS`，包含：
- `validation_id`, `formula_id`, `formula_name`
- `current_stage`, `stage_index`, `total_stages`
- `stage_status` (running/success/failed)
- `progress_percent`, `current_score`
- `message`（人类可读进度描述）

## 后果

### 正面
- **零人工干预**：从配方管理页面一键触发，后台异步执行全流程验证
- **可观测性**：WebSocket 实时推送 + 轮询双机制，前端随时可查进度
- **实验联动**：如关联实验记录，自动对比预测值与实测值，形成验证闭环
- **迭代友好**：支持只重试失败阶段，无需重跑全部流程
- **报告完整**：综合评分 + 分阶段详情 + 改进建议，可直接用于研发决策

### 负面
- 依赖各验证引擎（SafetyAlertSystem, CompatibilityChecker 等）的可用性，任一引擎故障需优雅降级
- WebSocket 连接在长耗时验证中需保持，网络中断后依赖轮询恢复
- 部分验证阶段（如稳定性预测）计算量较大，可能影响用户体验（需考虑超时和异步通知）
