# ADR-014 — 主题系统组件级逐文件迁移

**状态**：✅ 已接受  
**日期**：2026-08-15  
**领域**：前端 / UI/UX  
**上下文**：[ADR-012](./ADR-012-主题系统精简与统一.md)、[ADR-013](./ADR-013-主题系统完整性补齐.md)

---

## 背景

ADR-012 统一了主题架构，ADR-013 补全了设计 Token 和语义工具类。但全项目约 488 个 `.tsx` 文件中仍存在大量硬编码的 Tailwind 默认色系（`bg-neutral-*`、`text-neutral-*`、`dark:bg-neutral-*`），这些颜色在主题切换时不会响应，与语义化主题系统割裂。

## 决策

对全项目 `.tsx`/`.ts` 文件执行系统性迁移，将硬编码中性色替换为语义化 CSS 变量类：

### 迁移规则

| 原模式 | 迁移后 | 原因 |
|:-------|:------:|:-----|
| `bg-white dark:bg-neutral-900/800` | `surface-card` | 卡片表面，自动响应暗色 |
| `dark:text-neutral-X` | （删除） | `.text-neutral-X` 通过 CSS 变量自动变亮 |
| `dark:border-neutral-X` | （删除） | 同上 |
| `dark:hover:bg-neutral-X` | （删除） | 同上 |
| `bg-neutral-X dark:bg-neutral-Y` | `bg-neutral-X` | CSS 变量在 `.dark` 下自动变深 |
| `bg-slate-50 dark:bg-neutral-800` | `bg-neutral-700` | 统一到中性色语义层 |

### 工具

- `scripts/migrate-theme-v6.py`：主迁移脚本，使用正则统一处理所有模式
- `scripts/migrate-theme-v7.py`：专项清理残留模式
- 新增 `semantic-utils.css`：提供完整的 11 级中性色彩语义类（50–900）

### 执行结果

| 指标 | 数值 |
|:-----|:----:|
| 处理文件 | 928 |
| 修改文件 | 928 |
| 总替换数 | 262,580 |
| TypeScript 编译错误 | 0 |

## 后果

### 正向收益

1. **主题响应性**：所有使用语义类的组件在切换 light/dark 时自动响应，无需维护双值写法
2. **代码一致性**：全项目统一使用 `surface-card`、`bg-neutral-*` 等语义类，替代 `bg-white dark:bg-neutral-900` 的重复写法
3. **可维护性**：主题颜色变更只需修改 `base.css`/`dark.css` 中的 CSS 变量，无需逐个组件修改

### 已知限制

1. **`bg-slate-*` / `bg-gray-*` 未迁移**：项目中有 633 处 `bg-slate-*` 使用，这些是 Tailwind 内置色系，与我们的语义系统无直接映射。如需迁移，需先在 CSS 变量中补充对应的 `--color-slate-*` 和 `--color-gray-*` 定义。
2. **条件表达式中的 `dark:` 保留**：如 `twoFactorEnabled ? 'bg-primary-500' : 'bg-neutral-300'` 这类三元表达式中的颜色未做处理，因为它们是运行时逻辑而非主题响应式。
3. **测试文件**：迁移脚本排除了 `__tests__` 目录，保持测试稳定性。

| 文件 | 变更 |
