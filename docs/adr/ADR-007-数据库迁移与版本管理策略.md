# ADR-007: 数据库迁移与版本管理策略

## 状态
✅ 已接受 (2026-06-15)

## 上下文

RMFOOD 平台有 28+ ORM 模型，涉及频繁的数据模型变更。需要可靠的迁移策略:
1. 开发环境 ↔ 测试环境 ↔ 生产环境的 schema 同步
2. 数据种子/初始数据的自动化注入
3. 迁移回滚能力 (生产环境零停机)
4. 迁移审计追踪

## 决策

### 采用 Alembic + 版本化迁移

- 迁移文件: `backend/app/migrations/versions/`
- 迁移管理器: `backend/app/core/migration.py`
- 迁移审计: `backend/app/utils/migration_audit.py`

### 迁移规则

| 规则 | 说明 |
|:-----|:---------|
| 单向 | 每个迁移只向前，不回滚逻辑 |
| 幂等 | 使用 `IF NOT EXISTS` / `IF EXISTS` |
| 数据迁移 | 与 schema 迁移分离，单独版本 |
| 回滚 | 保留上一个版本的反向迁移 |

### 风险评估矩阵

| 风险等级 | 适用场景 | 审批要求 |
|:---------|:---------|:---------|
| LOW | 新增非空字段(有默认值)、新增表 | 自动执行 |
| MEDIUM | 修改列类型、新增外键 | 团队审核 |
| HIGH | 删除列、重命名表、数据转换 | DBA + 负责人 |
| CRITICAL | 表结构重组、跨库迁移 | 架构委员会 |
