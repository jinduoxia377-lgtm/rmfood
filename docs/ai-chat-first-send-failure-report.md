# 「首次对话失败（对话服务暂时不可用）」深度排查报告

- 日期：2026-10-23
- 范围：`/ai` 智能对话首次发送失败，提示「对话服务暂时不可用，请稍后重试」
- 结论：**服务端与源码层面已全部修复并验证通过**；用户侧若仍复现，**唯一能继续定位的输入是浏览器 DevTools 中 chat/stream 请求的状态码与响应体**。

## 1. 已定位并修复的根因

### 1.1 后端：流式超时/连接错误无自动重试（六期，已修）
- `llm_service.chat_stream`：连接阶段 Timeout/ConnectError 自动重试 1 次（500ms）；读流中断不重试。
- `chat.py`：超时类错误返回 503 + Retry-After + retryable。
- 验证：后端 pytest 80 passed。

### 1.2 前端：HTTP 错误状态码未纳入自动重试（已修）
- `sendMessageStream` 对 500/502/503/429/422 自动重试一次（600ms）。
- 验证：`chatServiceHttpRetry.test.ts` 4 passed。

### 1.3 前端：用户画像超长导致 422（已修）
- 前端注入 `user_profile_context` 前 `slice(0, 2000)`；后端上限放宽到 4000。
- 验证：2000 字符画像请求返回 200。

### 1.4 前端：专业配方卡渲染兜底（已修）
- `extractStructuredFallback`：即使标准检测失败，合法 blocks JSON 也渲染为专业配方卡，不裸显示 JSON。
- 验证：`formulaStructuredFallback.test.ts` 5 passed。

### 1.5 前端：裸 CSS 注释被渲染为文本（已修）
- `ChatTab.tsx` L558 裸注释改为 `{/* */}`。

## 2. 已完成的运行环境动作

- ✅ 重启前端 Vite（端口 3000），确认加载最新代码（`slice(0, 2e3)`）。
- ✅ 用户已重启后端（上限 4000 生效）。
- ✅ 实测：页面内 fetch 发送「高血糖多肽固体饮料配方」+ 2000 字符画像 → 200。

## 3. 关键排查发现（排除项）

- 后端直连：`/ai/chat/stream` 连续多次 200（响应 88~113 秒，较慢但正常）。
- 真实浏览器（Playwright）：页面正常渲染智能对话界面；但自动化输入**无法可靠同步 React 受控组件状态**，导致发送时 `question` 为空 → 后端 422（`question` 少于 1 字符）→ 前端兜底文案。**这是测试工具的假象，不是用户问题**（用户真实输入非空）。
- 系统代理（127.0.0.1:7897）已开启；脚本/部分客户端走代理时对 8000 返回 502，浏览器经 Vite 代理不受影响，但不能排除代理软件对用户浏览器首次请求的干扰。

## 4. 下一步（需要用户提供以继续定位）

请用户在**无痕窗口**打开 `http://localhost:3000/ai`，输入并发送后，按 `F12` → **Network**，找到 `chat/stream`（或 `ai/chat`）请求，复制给我：
1. **状态码**（200 / 4xx / 5xx / 0）；
2. **请求体**（Payload）；
3. **响应体**内容。

据此可字节级定位剩余问题。若更换浏览器/设备后不再失败，则为原浏览器缓存或代理插件导致。
