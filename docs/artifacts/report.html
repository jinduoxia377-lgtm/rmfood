第二部分：核心问题诊断

问题 1：算法引擎层 — 各自为战，缺乏统一调度

现状：4个优化引擎（GA / Bayesian / NSGA-II / NSGA-III）完全独立，没有统一的调度层。

引擎 文件 编码方式 适应度评估 约束处理 与其他引擎的关系
Bayesian bayesian_formula_optimizer.py 实数向量 [0,1]^N 加权求和 ❌ 无 独立
GA genetic_formula_optimizer.py 实数编码 {herb_id: dosage} 加权求和 ⚠️ 软惩罚 独立
NSGA-II multi_objective_optimizer.py 实数编码 {herb_id: dosage} 7维Pareto ⚠️ 软惩罚 独立
NSGA-III formula/ratio_optimizer.py 实数编码 {ingredient: ratio%} 4维Pareto ⚠️ 惩罚函数 独立

问题： - 用户无法根据场景选择最优引擎 - 引擎之间无法协作（如GA选原料 + NSGA-III定配比） - 重复代码多（每个引擎都有自己的药材选择、适应度评估逻辑） - 没有引擎使用 NutritionEngine 进行营养硬约束校验

问题 2：管线层 — 骨架化严重，大量模拟数据

现状：AIService 的评估管线中，多个组件是骨架实现：

组件 文件 状态 问题
FormulaGPT ai_models/formula_gpt.py ⚠️ 骨架 注释写"接入vLLM端点后即可启用"，当前是规则回退
SynergyNet ai_models/synergy_net.py ⚠️ 部分实现 使用预计算协同矩阵，无真实ML模型
SafetyChecker ai_models/safety_checker.py ✅ 较完整 十八反/十九畏规则完整，但缺少法规数据库对接
TastePredictor ai_models/taste_predictor.py ⚠️ 骨架 基于简单规则，无真实口感预测模型
StabilityModel ai_models/stability_model.py ⚠️ 骨架 基于简单规则，无真实稳定性预测
PeptideScorer ai_models/peptide_scorer.py ⚠️ 骨架 随机评分模拟

影响：配方生成的质量高度依赖规则引擎，AI模型的"智能"成分很低。

问题 3：营养引擎 — 与算法引擎完全脱节

现状：NutritionEngine 是一个独立模块，提供营养计算、成本核算、合规检查。但：

  • 没有任何算法引擎调用 NutritionEngine
  • 算法引擎的适应度评估使用简化的功效评分，而非真实营养计算
  • 营养约束（蛋白质≥12%等）无法作为硬约束传入优化过程
  • 成本计算在适应度函数中是简化的线性估算，而非精确计算

这是最大的架构缺陷：营养引擎和算法引擎是"两条平行线"。

问题 4：贝叶斯优化器 — 实现有数学缺陷

现状：BayesianFormulaOptimizer 的自定义GP实现存在以下问题：

  1. 核矩阵求逆使用高斯消元：O(n³) 复杂度，n>100时性能急剧下降
  2. 无超参数优化：length_scale 和 sigma_f 是固定值，未通过边际似然优化
  3. 无噪声处理：sigma_n=0.1 固定，无法处理不同噪声水平
  4. EI采集函数的随机重启策略过于简单：仅10次重启，可能错过全局最优
  5. 搜索空间是连续的 [0,1]^N：N=候选药材数，高维空间GP效果差

问题 5：GA引擎 — 搜索空间耦合

现状：GeneticFormulaOptimizer 使用实数编码 {herb_id: dosage}：

  • 同时优化"选什么"和"放多少"
  • 搜索空间维度 = 候选药材数 × 用量精度
  • 变异操作可能产生不合理的用量（如黄芪用0.1g）
  • 无法保证营养约束满足

问题 6：NSGA-II引擎 — 最完整但仍有缺陷

现状：multi_objective_optimizer.py 是项目中最完整的算法实现：

  • ✅ 真正的NSGA-II（快速非支配排序 + 拥挤度距离）
  • ✅ SBX交叉 + 多项式变异
  • ✅ 7维目标函数（功效/安全/口感/成本/协同/稳定性/ADMET）
  • ✅ 中医配伍知识库（十八反/十九畏/性味归经）
  • ❌ 仍然是实数编码，搜索空间耦合
  • ❌ 无LP/QP层进行精确配比优化
  • ❌ 与NutritionEngine脱节

3.1 核心创新：统一调度器 + 引擎协作

设计思路：不是替换现有引擎，而是建立一个统一调度层，让各引擎协作。

class UnifiedFormulaOptimizer:
    """
    统一配方优化调度器

    核心思想：
    1. 根据问题特征自动选择最优引擎组合
    2. 引擎之间可以协作（如GA选原料 + LP定配比）
    3. 统一的适应度评估接口（接入NutritionEngine）
    """

    def __init__(self):
        self.engines = {
            'bayesian': BayesianFormulaOptimizer(),
            'ga': GeneticFormulaOptimizer(),
            'nsga2': NSGAIIOptimizer(),
            'nsga3': RatioOptimizer(),
        }
        self.nutrition_engine = None  # 注入
        self.lp_solver = None  # 注入

    async def optimize(self, request: OptimizationRequest) -> OptimizationResult:
        """
        智能调度：根据问题特征选择最优策略
        """
        # 策略选择
        strategy = self._select_strategy(request)

        if strategy == 'ga_lp_hybrid':
            return await self._ga_lp_optimize(request)
        elif strategy == 'bayesian_lp_hybrid':
            return await self._bayesian_lp_optimize(request)
        elif strategy == 'nsga2_pareto':
            return await self._nsga2_optimize(request)
        else:
            return await self._default_optimize(request)

    def _select_strategy(self, request: OptimizationRequest) -> str:
        """
        策略选择逻辑：
        - 候选原料 > 20种 → GA+LP（大规模组合搜索）
        - 营养约束严格 → GA+LP（硬约束保证）
        - 需要Pareto前沿 → NSGA-II（多目标权衡）
        - 实验数据少 → Bayesian+LP（样本效率高）
        """
        if request.require_pareto:
            return 'nsga2_pareto'
        elif len(request.candidate_herbs) > 20:
            return 'ga_lp_hybrid'
        elif request.strict_nutrition_constraints:
            return 'ga_lp_hybrid'
        elif request.experimental_data_available:
            return 'bayesian_lp_hybrid'
        else:
            return 'ga_lp_hybrid'

3.2 GA-LP 混合引擎 — 核心实现

这是整个方案的核心，将你的GA-LP思路与项目现有架构深度融合。

3.2.1 外层GA：二进制编码原料选择

class BinaryGAOptimizer:
    """
    二进制GA — 决定"用不用"每种原料

    染色体: [1, 0, 1, 1, 0, ...] (0/1向量)
    基因i = 1 → 选用候选原料i
    基因i = 0 → 不选用候选原料i
    """

    def __init__(self, config: GAConfig):
        self.config = config
        self.candidate_herbs: List[str] = []  # 候选原料列表
        self.lp_solver = None  # LP求解器注入
        self.nutrition_engine = None  # 营养引擎注入

    async def optimize(self, target_effects, constraints) -> List[FormulaResult]:
        # Step 1: 预筛选候选原料池（复用现有 _select_herbs 逻辑）
        self.candidate_herbs = await self._select_candidate_herbs(
            target_effects, constraints
        )
        # 将候选池压缩到 15-25 种（控制搜索空间 2^15 ~ 2^25）
        self.candidate_herbs = self.candidate_herbs[:25]

        n = len(self.candidate_herbs)

        # Step 2: 初始化种群（二进制编码）
        population = self._init_binary_population(n)

        # Step 3: 进化迭代
        for gen in range(self.config.generations):
            # 对每个个体：调用LP层求解精确配比
            for individual in population:
                # 解码：获取选中的原料列表
                selected_herbs = [
                    self.candidate_herbs[i] 
                    for i in range(n) 
                    if individual.genes[i] == 1
                ]

                # LP层：求解精确配比
                lp_result = await self._solve_lp(selected_herbs, constraints)

                if lp_result.feasible:
                    # LP可行：获取精确配比、最低成本、营养矩阵
                    individual.ratios = lp_result.ratios
                    individual.lp_cost = lp_result.min_cost
                    individual.nutrition = lp_result.nutrition

                    # 适应度评估（多目标）
                    individual.fitness = await self._evaluate_fitness(
                        selected_herbs, lp_result.ratios, target_effects
                    )
                else:
                    # LP不可行：赋予极低适应度
                    individual.fitness = 0.001

            # 遗传操作：选择 + 交叉 + 变异
            population = self._evolve(population)

        # Step 4: 返回Top-N结果
        return self._extract_results(population)

3.2.3 适应度评估：多目标综合

class MultiObjectiveEvaluator:
    """
    多目标适应度评估器

    评估维度：
    1. 成本效率 (来自LP层精确值)
    2. 营养均衡 (来自NutritionEngine)
    3. 协同效应 (来自SynergyNet)
    4. 口感评分 (来自TastePredictor)
    5. 安全性 (来自SafetyChecker)
    """

    async def evaluate(
        self,
        selected_herbs: List[str],
        ratios: Dict[str, float],
        target_effects: List[str]
    ) -> float:
        # 成本分 (LP精确值)
        cost_score = 1.0 / (1.0 + lp_result.min_cost)

        # 营养分 (NutritionEngine精确计算)
        nutrition_score = await self.nutrition_engine.evaluate_balance(
            selected_herbs, ratios
        )

        # 协同分 (SynergyNet)
        synergy_score = await self.synergy_net.evaluate(selected_herbs, ratios)

        # 口感分 (TastePredictor)
        taste_score = await self.taste_predictor.predict(selected_herbs, ratios)

        # 安全分 (SafetyChecker)
        safety_score = await self.safety_checker.evaluate(selected_herbs)

        # 加权综合
        fitness = (
            w1 * cost_score +
            w2 * nutrition_score +
            w3 * synergy_score +
            w4 * taste_score +
            w5 * safety_score
        )
        return fitness

3.3 贝叶斯优化升级：与LP层协作

思路：保留贝叶斯优化的样本效率优势，但将其搜索空间从连续用量空间改为离散原料组合空间。

class BayesianLPHybrid:
    """
    贝叶斯 + LP 混合引擎

    外层：贝叶斯优化搜索原料组合（离散空间）
    内层：LP求解精确配比

    优势：
    - 样本效率高于GA（适合实验成本高的场景）
    - LP层保证营养硬约束
    - 可以复用现有BayesianFormulaOptimizer的GP实现
    """

    async def optimize(self, target_effects, constraints):
        # 候选原料池
        candidates = self._select_candidates(target_effects)

        # 贝叶斯优化（搜索离散组合空间）
        for round_idx in range(self.config.n_rounds):
            # GP建模：原料组合 → 适应度
            # EI采集：选择下一个最有潜力的原料组合
            selected_combo = self._ei_select(candidates, gp_model)

            # LP层：求解精确配比
            lp_result = await self._solve_lp(selected_combo, constraints)

            if lp_result.feasible:
                fitness = await self._evaluate(selected_combo, lp_result.ratios)
                # 更新GP模型
                gp_model.update(selected_combo, fitness)

        return self._extract_best()

3.4 NSGA-II升级：接入NutritionEngine

思路：保留NSGA-II的多目标Pareto优势，但将NutritionEngine接入适应度评估。

class EnhancedNSGAIIOptimizer:
    """
    增强版NSGA-II — 接入NutritionEngine进行精确营养评估

    改进点：
    1. 适应度评估从简化评分 → 精确营养计算
    2. 约束处理从软惩罚 → NutritionEngine硬约束校验
    3. 新增营养偏差目标（最小化与目标营养的偏差）
    """

    def __init__(self, nutrition_engine: NutritionEngine):
        self.nutrition_engine = nutrition_engine

    async def evaluate_objectives(self, individual):
        """7维目标函数（增强版）"""
        # 原有目标（保留）
        efficacy = self._calc_efficacy(individual)
        safety = self._calc_safety(individual)
        taste = self._calc_taste(individual)
        synergy = self._calc_synergy(individual)
        stability = self._calc_stability(individual)

        # 新增目标（来自NutritionEngine）
        nutrition_balance = await self.nutrition_engine.calc_balance_score(
            individual.genes
        )
        cost = await self.nutrition_engine.calc_exact_cost(individual.genes)

        return {
            'efficacy': efficacy,
            'safety': safety,
            'taste': taste,
            'synergy': synergy,
            'stability': stability,
            'nutrition_balance': nutrition_balance,  # 新增
            'cost': cost,  # 精确成本
        }

3.5 NutritionEngine集成：从独立到核心

思路：将NutritionEngine从独立服务提升为所有算法引擎的核心依赖。

class NutritionAwareOptimizer:
    """
    营养感知优化器基类

    所有算法引擎继承此类，自动获得：
    1. 精确营养计算能力
    2. 营养硬约束校验
    3. 成本精确计算
    4. 合规性预检查
    """

    def __init__(self, nutrition_engine: NutritionEngine):
        self.nutrition = nutrition_engine

    async def validate_nutrition(
        self, herbs: List[str], ratios: Dict[str, float]
    ) -> NutritionValidation:
        """
        营养硬约束校验

        Returns:
            NutritionValidation:
                - is_feasible: bool
                - violations: List[str] (不满足的约束)
                - nutrition_matrix: Dict[str, float] (完整营养矩阵)
        """
        # 调用NutritionEngine计算精确营养
        nutrition_result = await self.nutrition.calculate_nutrition(
            formula_id=0,  # 临时配方
            formula_name="temp",
            ingredients=[
                {"ingredient_id": h, "amount_d": ratios[h]} 
                for h in herbs
            ]
        )

        # 检查约束
        violations = []
        for constraint in self.nutrition_constraints:
            value = nutrition_result.nutrients_per_100g.get(constraint.nutrient)
            if value is not None:
                if constraint.min is not None and value < constraint.min:
                    violations.append(f"{constraint.nutrient}低于下限")
                if constraint.max is not None and value > constraint.max:
                    violations.append(f"{constraint.nutrient}超过上限")

        return NutritionValidation(
            is_feasible=len(violations) == 0,
            violations=violations,
            nutrition_matrix=nutrition_result.nutrients_per_100g
        )
