## 1️⃣ 系统概述

### 系统定位
RMFOOD是一个药食同源功能性食品专业配方研发平台，旨在帮助研发人员快速设计、优化和验证食品配方。

### 核心功能模块

| 模块 | 功能描述 |
|------|----------|
| 🧪 智能配方 | AI驱动的配方设计与优化 |
| 🤖 AI助手 | 智能推荐与分析 |
| 🔬 实验管理 | 实验数据管理与分析 |
| 📚 知识库 | 成分与药材数据库 |
| 🔄 工作流引擎 | 自动化流程编排 |
| 📊 数据分析 | 可视化报表与洞察 |

## 3️⃣ 架构设计

### 架构风格
- **微服务架构**: 后端采用模块化设计，各模块独立部署
- **前后端分离**: 前端通过API与后端通信
- **事件驱动**: 支持WebSocket实时通信

### 分层架构

```
┌─────────────────────────────────────────────────────────┐
│                    前端展示层 (Frontend)                │
│  React + TypeScript + Tailwind CSS                      │
├─────────────────────────────────────────────────────────┤
│                    API网关层 (API Gateway)              │
│  FastAPI + Security Middleware                         │
├─────────────────────────────────────────────────────────┤
│                    业务逻辑层 (Service Layer)            │
│  AI服务 / 配方服务 / 实验服务 / 用户服务                 │
├─────────────────────────────────────────────────────────┤
│                    数据访问层 (Data Layer)               │
│  SQLAlchemy + PostgreSQL + Redis                       │
├─────────────────────────────────────────────────────────┤
│                    外部集成层 (External)                 │
│  LLM API / TCMSP / DFBP / 第三方服务                    │
└─────────────────────────────────────────────────────────┘
```

### 核心设计原则

1. **单一职责**: 每个模块只负责一个功能领域
2. **依赖倒置**: 高层模块不依赖低层模块，都依赖抽象
3. **开闭原则**: 对扩展开放，对修改封闭
4. **接口隔离**: 客户端只依赖它需要的接口
5. **高内聚低耦合**: 模块内部紧密，模块间松耦合

## 5️⃣ 数据流

### 典型数据流程

#### 1. 用户登录流程

```
用户 → 前端登录页 → API网关/auth/login → 用户服务验证 → 返回JWT → 前端存储Token
```

#### 2. 配方创建流程

```
用户 → 前端配方设计器 → API网关/formulas → 配方服务 → 
  ├─→ AI服务(推荐成分)
  ├─→ 验证安全性
  └─→ 数据库存储
     → 返回配方ID
```

#### 3. AI分析流程

```
用户请求 → API网关/ai/analyze → AI服务 → 
  ├─→ 调用LLM API
  ├─→ 查询知识库
  └─→ 协同效应计算
     → 返回分析结果
```

### 数据实体关系

```
用户(Users) ←─── 配方(Formulas) ←─── 成分(Ingredients)
     │                 │                    │
     │                 ▼                    │
     │           实验(Experiments)          │
     │                 │                    │
     └─────────────── 日志(AuditLogs) ←─────┘
```

## 6️⃣ 安全架构

### 认证机制

- **JWT Token**: 无状态认证
- **密码哈希**: bcrypt算法
- **账户锁定**: 连续5次失败锁定15分钟
- **密码策略**: 8位以上，含大小写、数字、特殊字符

### 授权机制

- **RBAC**: 基于角色的访问控制
- **权限矩阵**: 角色-资源-操作映射
- **最小权限原则**: 只授予必要权限

### 安全防护

| 防护措施 | 说明 |
|----------|------|
| HTTPS | 传输加密 |
| CORS | 跨域控制 |
| CSRF | 跨站请求伪造防护 |
| SQL注入防护 | ORM参数化查询 |
| XSS防护 | 输入过滤与转义 |
| 请求限流 | 防止暴力攻击 |
