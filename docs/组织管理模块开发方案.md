### 现有计划定义（`PLAN_LIMITS`，可直接复用）

- `enterprise`：无限（-1）

## 二、功能范围（本期"真正的功能"）

### 1. 组织生命周期
- 创建（向导已有，接真实接口）、列表（我的组织/全部/回收站）、详情、编辑基本信息/Logo/设置。
- 归档 / 恢复 / 克隆（**深拷贝**：成员、团队、权限设置一起复制）。
- 删除（仅 OWNER；软删除进回收站，回收站可彻底删除）。

### 2. 成员管理（真实化）
- 邀请：按邮箱邀请（系统已有用户直接入组；非系统用户生成邀请记录 + 邮件/站内通知）。
- 成员列表：角色、加入时间、最近活跃。
- 角色变更：owner / admin / member / viewer。
- 停用 / 恢复 / 移除成员。
- **批量操作**（本期重点补齐）：
  - 批量改角色（按成员角色枚举）
  - 批量停用 / 批量恢复
  - 批量移除
  - 批量导出成员（CSV/JSON）

### 3. 团队管理
- 创建 / 编辑 / 删除团队；团队列表；成员分配到团队（`team_members`）。

### 4. 权限矩阵（真实读写）
- 权限项：`member_management`、`team_management`、`formula_access`、`experiment_access`、`data_export`、`api_access`。
- 按角色（owner/admin/member/viewer）设置默认权限模板；OWNER/ADMIN 可修改；保存到 `organizations.settings.permissions`。
- 前端权限矩阵勾选 → `PUT /organizations/{id}/permissions` 真实保存。

### 5. 配额与用量（真实统计）
- 真实 SQL 统计：成员数、团队数、配方数（按 creator/org 关联）、存储用量、API 调用量（当日）、AI 生成量（当日）。
- 前端展示"用量进度条（已用/上限）"，超限时给出升级引导。

### 6. 数据分析（真实数据）
- 成员趋势（近 7/30/90 天加入/移除）、团队数量、存储趋势、API 调用/错误率（来自日志聚合）。

### 7. 审计日志（真实落库）
- 记录成员变更、权限变更、计划变更、导出、克隆、删除等操作到 `organization_activities`。
- 前端审计面板分页展示（操作人/动作/时间/IP）。

### 8. 数据导出（真实数据）
- 导出组织成员、团队、权限配置为 JSON / CSV（下载文件）。

### 9. 订阅与计费（免费 vs 付费核心）
- **订阅管理**：查看当前计划、用量、升级/降级/取消订阅。
- **计划对比页**：免费版 / 专业版 / 企业版功能与价格。
- **升级流程**：选择计划 → 确认 → 生成订单 →（本期）**模拟支付**成功 → 更新 `organizations.plan` 与 `subscriptions` 状态。
- **付费墙**：免费版超限时，写操作（新建第 6 个成员、第 3 个团队、超额 AI 等）被拦截，弹出升级引导。

## 三、免费 vs 付费模型（定价方案）

### 计费粒度
- **按组织订阅**（不是按用户）。组织创建者/管理员付费，成员免费加入。

### 各版本边界
| 维度 | 免费版 Free | 专业版 Pro | 企业版 Enterprise |
|---|---|---|---|
| 价格 | **¥0** | **¥199/月** 或 **¥1999/年** | **定制（建议 ¥1999/月起）** |
| 成员数 | ≤ 5 | ≤ 20 | 无限 |
| 团队数 | ≤ 2 | ≤ 10 | 无限 |
| 配方数 | ≤ 100 | ≤ 1000 | 无限 |
| 存储 | 1 GB | 10 GB | 无限 |
| API 调用/天 | 1,000 | 10,000 | 无限 |
| AI 生成/天 | 10 | 100 | 无限 |
| 高级分析 | ❌ | ✅ | ✅ |
| API 访问 | ❌ | ✅ | ✅ |
| 自定义品牌 | ❌ | ✅ | ✅ |
| 审计日志 | 7 天 | 180 天 | 永久 |
| 专属经理 / SLA / SSO / 私有部署 | ❌ | ❌ | ✅ |

### "谁免费、谁付费"判定规则
1. **默认免费**：所有注册用户登录后默认处于免费版组织（个人组织 ≤5 人完全免费）。
2. **触发付费**：当组织**实际用量超过免费版上限**（第 6 个成员、第 3 个团队、第 101 个配方、AI 额度用尽等）时，执行超额操作的成员会看到**升级引导**，该操作被拦截（只读或提示）。
3. **自愿升级**：组织 OWNER/ADMIN 可在"订阅"页随时升级到 Pro/Enterprise。
4. **降级规则**：降级后如用量超限，超限功能进入只读，直到删除多余资源或重新升级。
5. **年付优惠**：Pro 年付约 8.3 折（¥1999/年）。

### 支付合规说明（本期边界）
- 本期**不接入真实支付网关**（避免支付资质/合规问题），采用**模拟支付/订单**流程（生成订单 → 模拟支付成功 → 订阅生效）。
- 后端预留 `payment_provider` / `external_id` 字段，后续可平滑接入 Stripe / 支付宝 / 微信支付。

## 四、技术方案

### 后端
1. **新增表**：
   - `subscriptions`：`id, organization_id(FK), plan, status(active/trial/canceled/expired), started_at, expires_at, payment_provider, external_id, created_at, updated_at`。
   - `billing_orders`：`id, organization_id, plan, amount_cents, currency, status(pending/paid/failed), provider_order_id, created_at`。
   - `organization_invitations`：`id, organization_id, email, role, token, status(pending/accepted/expired), invited_by, created_at`。
2. **重写 `multi_tenant_service` 占位方法**：
   - `get_quota_usage`：真实 SQL 计数（members/teams/formulas/storage/api_calls/ai_generations）。
   - `get_analytics`：按天聚合成员/存储/API 数据。
   - `get_audit_log`：读 `organization_activities`；新增 `record_activity()` 写审计。
   - `export_organization`：导出成员/团队/权限设置为 JSON/CSV。
   - `clone_organization`：深拷贝（成员、团队、权限设置）。
   - 新增批量成员操作（`batch_change_role`、`batch_suspend`、`batch_resume`、`batch_remove`、`batch_export`）。
3. **新增订阅接口**：
   - `GET /organizations/{id}/subscription`：当前订阅与用量。
   - `POST /organizations/{id}/subscription/upgrade`：升级计划（生成订单+模拟支付）。
   - `POST /organizations/{id}/subscription/cancel`：取消续费。
   - `GET /organizations/{id}/usage`：真实用量（含超额标记）。
4. **权限与超额拦截**：
   - 在创建成员/团队/配方/AI 等写路径统一检查 `PLAN_LIMITS`，超限返回 `403 + upgrade_required` 结构化错误。

### 前端
1. **OrganizationsPage 去 `@ts-nocheck`**，修正类型错误。
2. **批量操作真实化**：
   - 批量改角色：选择目标角色 → 确认 → `POST /organizations/{id}/members/batch-role`。
   - 批量停用/恢复/移除：调用对应批量接口。
   - 批量导出：调用导出接口下载 CSV。
3. **权限矩阵真实化**：勾选 → `PUT /permissions`；读取真实配置回显。
4. **配额展示**：每个组织详情卡片显示用量进度条（成员/团队/存储/API/AI），超限变红 + 升级按钮。
5. **订阅管理页**：当前计划卡片、价格、升级/降级/取消按钮、模拟支付弹窗、订单成功提示。
6. **付费墙组件**：超限操作时弹出升级引导（`UpgradePromptDialog`）。
7. **数据分析图表**：接入真实 `/analytics` 数据（成员趋势折线、存储柱状、API 统计）。
8. **审计日志面板**：接入 `/audit-log` 分页展示。

### 数据与安全
- 所有组织写操作统一做成员角色校验（owner/admin/member/viewer）。
- 审计动作必须落库。
- 订阅状态变更写审计。
