## 一、宣传的核心判断（先想清楚再动笔）

### 1.1 我们卖的不是"AI 写配方"，而是"可被审阅的研发证据链"

药食同源功能性食品行业的真实痛点，不是"想不出配方"，而是：
配方说不清**为什么这么配**、过不了**安全合规**、走不到**实验验证与 COA**、协作留不下**审计痕迹**。

所以宣传主线不应是"AI 帮你生成配方"（同质化、易被当成玩具），
而应是：**把传统配伍智慧，翻译成可量化、可追溯、可合规交付的研发全流程。**

一句话主张（Hero 主标题候选）：

> **从"君臣佐使"到可交付的配方证据链**
> 传统中医食疗智慧 × 网络药理学 × 多目标优化算法——
> 覆盖 配方设计 → 安全合规 → 实验验证 → COA 出具 → 学术报告 的完整研发链路。

副标题强调"全链路 + 可交付物"，而非单点生成。

### 1.2 三类受众，三种说服重点

| 受众 | 他关心什么 | 宣传重点 | 落点模块 |
|:-----|:----------|:---------|:---------|
| **配方研发人员/科研团队** | 配方是否有科学依据、能否发论文/报成果 | 网络药理学、多目标优化、肽结构分析、学术报告导出 | Algorithms / Peptide / Academic |
| **功能食品企业/研发主管** | 合规能不能过、成本与适口性怎么平衡、能否量产 | 安全合规引擎、口感/稳定性预测、批次溯源、COA、多租户协作 | Safety / Taste / Stability / Batch / Compliance |
| **企业决策者/投资人** | 是否企业级、是否可私有化、是否有工程护城河 | 890 端点、双端交付、多租户 RBAC、Docker 一键部署、语义化版本治理 | Trust / Metrics / Enterprise |

> 宣传页默认主线面向**研发人员 + 企业研发主管**，投资人口味通过"信任与规模"区块照顾。

### 1.3 诚实边界 = 信任资产（必须写进页脚与免责）

平台自身定位就是"循证、克制"，宣传口径必须与之自洽：
- 强调"辅助研发/辅助调理，不替代医师诊断与治疗"；
- 功效类表述用"现有研究表明可能具有……潜力"，不承诺疗效；
- 数据来源可溯源（TCMSP / DFBP / Open Food Facts / PubMed / 国家标准 GB 16740-2014）。

**这反而是差异化卖点**：在一个人人夸大疗效的赛道，"克制、可溯源"就是高级感。

## 三、可信数字口径（宣传页可直接引用，注明实测基准）

> 全部来自 README 实测（基准提交 `216c247`，2026-10-28）。宣传页使用时建议统一脚注口径来源。

**规模与工程**
- 567 次 git 提交（2026-06-10 → 2026-10-27）
- 后端 FastAPI **890 个 API 端点** / 783 个应用代码文件
- 前端 React 19 + TS，**TypeScript 错误 0**
- **75 个** Alembic 数据库迁移版本
- 双端交付：Web（33 个一级页面域）+ 微信小程序（31 组件 / 3 分包 / 14 页面域）
- **48 篇**架构决策记录（ADR）

**算法与 AI**
- **7 种**优化算法引擎统一调度（GA / NSGA-III / 贝叶斯 / MOEA-D-CMA-ES / BinaryGA-MILP / Bandit / 神经网络）
- NSGA-III 支持 **8 维目标** Pareto 优化；UCB1 Bandit 自动选择最优策略
- 完整优化管线 P95 ≈ **3.2s**（实验室内部压测示例，需保留"示例"措辞）
- **5+** LLM 端点适配（DeepSeek / GPT-4 / 智谱 / 通义千问 / vLLM 自定义）
- RAG 检索增强：ChromaDB + FastEmbed 本地 embedding，服务级端到端闭环

**数据与知识**
- 知识图谱约 **14.7K 实体节点 / 24 万关联边**
- 活性肽 **7,660+ 结构**（PepINVENT + RDKit + PyTorch 管线）
- 药材数据四源融合：TCMSP / SymMap / RMCHM / CFAM
- 食品原料：Open Food Facts 同步 + 本地化映射

**安全与合规**
- **61 类**内置安全阈值（多肽/多糖/皂苷/黄酮/生物碱等）
- 三级预警（INFO/WARN/CRITICAL）
- 106 种法定配伍禁忌条目
- PopPK/PD 药效动力学模型 + 特殊人群（孕妇/儿童/老年）剂量调整
- 多租户行级隔离 + RBAC **5 级**角色 + GLP 审计

> ⚠️ **口径纪律**：成熟度百分比、"行业领先"类无实测支撑的表述一律不写。
> 涉及"AI 助手中心 v8/v9""引擎 V4"等，均为**模块内部代号**，与平台 v2.0.0 正交，宣传页统一对外讲"平台 v2.0.0"，不暴露内部代号以免混淆。

## 四、文案基调与视觉调性

**文字**
- 专业、循证、克制；动词驱动，少形容词。
- 每个能力点都配一个"关键数字 + 技术标签 + 三步流程"，延续现有 features.ts 的好范式。
- 中英双语（复用 i18next，105 个 i18n 文件基础）。

**视觉**
- 沿用现有三维配色语义：智能研发=翡翠绿、数据能力=靛蓝、企业协作=琥珀（见 dimensionConfig）。
- 中式底色（药食同源、君臣佐使）+ 现代数据可视化（图谱、Pareto 前沿、雷达），形成"传统智慧 × 现代工程"的视觉张力。
- 强调留白与层级，避免功能堆砌感。
