## 四、API接口设计

### 4.1 药材相关

```javascript
// 获取药材列表
GET /api/v1/herbs
参数: page, limit, category, nature, is_food_homology, keyword

// 获取药材详情
GET /api/v1/herbs/:rmchm_id
响应: {
  herb: {...},
  compounds: [...],
  targets: [...],
  diseases: [...]
}

// 搜索药材
GET /api/v1/herbs/search?keyword=xxx&category=xxx
```

### 4.2 配方相关

```javascript
// 生成配方
POST /api/v1/formulas/generate
请求: {
  symptoms: "症状描述",
  goals: ["调理目标"],
  constraints: { pregnant: false, allergies: [] }
}
响应: {
  formula: {...},
  analysis: {...},
  ingredients: [...]
}

// 保存配方
POST /api/v1/formulas/save
```

### 4.3 分析相关

```javascript
// 获取统计数据
GET /api/v1/analytics/summary
响应: {
  total_herbs: 714,
  homology_count: 127,
  category_distribution: [...],
  nature_distribution: [...]
}
```

## 七、数据质量评估

### 7.1 质量评分标准

| 维度 | 权重 | 评分规则 |
|------|------|---------|
| 基础信息完整度 | 15% | 名称、拼音、拉丁名齐全 |
| 传统属性完整度 | 20% | 四气、归经、功效齐全 |
| 药理学数据完整度 | 20% | OB%、DL值、化合物数量 |
| 图片资源 | 10% | 有标准药材图片 |
| 多源交叉引用 | 20% | TCMSP/SymMap双源数据 |
| 药食同源标记 | 15% | 符合国家目录 |

### 7.2 当前质量分布

| 质量等级 | 数量 | 占比 |
|---------|------|------|
| 高质量(>0.8) | ~100条 | ~14% |
| 中质量(0.5-0.8) | ~380条 | ~53% |
| 低质量(<0.5) | ~234条 | ~33% |

### 7.3 改进建议

1. **补充关联表数据**：导入化合物、靶点、疾病详细数据
2. **完善低质量药材**：补充四气、归经等传统属性
3. **扩充图片资源**：逐步纳入非药食同源药材图片
4. **数据质量监控**：建立定期审核机制
