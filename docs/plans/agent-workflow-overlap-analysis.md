**分析人**：AI 架构专家

**版本**：v1.0  
**状态**：待决策

## 执行摘要

经过系统性架构审查，发现 **Agent 工作流** 与 **智能对话** 两个模块存在 **79% 的功能重叠**，主要体现在：

| 维度 | 重叠度 | 严重性 |
|------|--------|--------|
| 代码实现 | 99% (443行 vs 434行) | 🔴 高 |
| API 调用 | 80% (共享底层引擎) | 🔴 高 |
| 用户场景 | 60% (相同快捷问题) | 🟡 中 |
| 维护成本 | 2x 重复工作量 | 🔴 高 |

**核心结论**：两个模块本质上是同一系统的两种展示模式，建议采用**渐进式合并策略**，在保持向后兼容的前提下，逐步统一架构。

## 二、问题根因分析

### 2.1 历史遗留问题

```
时间线：
2026-06 ──→ 初始设计：单一聊天界面
    │
2026-07 ──→ 新增工作流需求，创建独立 AgentWorkflowTab
    │
2026-08 ──→ 发现问题：两个模块高度重叠
```

**根因**：需求迭代时未进行架构评审，导致重复建设。

### 2.2 设计缺陷

| 缺陷类型 | 具体表现 | 影响 |
|---------|---------|------|
| 职责不清 | 两个模块都负责消息、工具、阶段展示 | 代码重复 |
| 抽象不足 | 缺少统一的 Agent 执行 Hook | 逻辑分散 |
| 扩展性差 | 新增模式需修改多处代码 | 维护成本高 |

## 三、解决方案（三级推荐）

### 方案 A：激进合并（推荐指数：⭐⭐⭐）

**策略**：立即合并为单一模块

```
实施步骤：
1. 删除 AgentWorkflowTab.tsx
2. 在 ChatTab 添加工作流模式切换
3. 统一为 useUnifiedAgent hook

优点：
  • 代码量减少 50%
  • 用户体验统一
  • 维护成本降低

风险：
  • 用户习惯需要适应
  • 需重新测试所有场景
  • 短期工作量较大
```

**适合场景**：团队资源充足，可接受短期波动。

---

### 方案 B：渐进合并（推荐指数：⭐⭐⭐⭐⭐）

**策略**：分三个阶段，保持向后兼容

#### Phase 1：组件抽取（1周）
```typescript
// shared/AgentComponents.tsx
export {
  AgentMessageList,      // 统一消息列表
  ToolCallDisplay,       // 统一工具调用显示
  StageProgress,         // 统一阶段进度
  ErrorBoundary,         // 统一错误处理
}
```

**验收标准**：
- [ ] 重复代码率 < 30%
- [ ] 新增组件通过单元测试
- [ ] 原有功能不受影响

#### Phase 2：Hook 统一（2周）
```typescript
// hooks/useUnifiedAgent.ts
export function useUnifiedAgent() {
  const [messages, setMessages] = useState(...)
  const [tools, setTools] = useState(...)
  const [stages, setStages] = useState(...)

    // 统一执行逻辑

}
```

**验收标准**：
- [ ] AgentWorkflowTab 和 ChatTab 使用同一 Hook
- [ ] 行为完全一致
- [ ] 性能无退化

#### Phase 3：入口统一（1个月）

**验收标准**：
- [ ] 单一导航入口
- [ ] 智能模式切换
- [ ] 用户满意度 > 90%
