1. 项目概述

1.1 项目定位

RMFOOD（Recipe Management for Optimal Organic Design）是一款面向药食同源功能性食品研发的 AI 驱动企业级配方设计平台，由莱茵(厦门)分子生物科技有限公司主导建设。平台覆盖从原料筛选、配方设计、功效评估到合规审查的完整研发生命周期。

> 重要声明：本节是对 ADR-001（六边形架构）实施的反思与收敛，由实际代码审查发现后新增。

4.1 问题诊断

4.3 新架构约束

层级禁止事项允许事项
**Controller**直接操作数据库、包含业务逻辑路由注册、请求解析、权限校验、响应格式化

4.4 六边形架构的保留价值

虽然全局采用三层架构，但以下局部领域仍受益于六边形思想：

1. AI 服务（services/ai/）：LLM Provider 工厂（策略模式）、RAG 向量存储接口，实质上是端口/适配器模式

2. 知识图谱（services/kg/）：Neo4j/内存双实现，通过 graph_service.py 接口隔离

3. 搜索服务（services/search/）：BM25/Elasticsearch/ChromaDB 三种实现，统一通过 hybrid_search.py 接口

> 结论：全局三层 + 局部六边形 = 最务实的工程选择

21.2 技术决策（ADR-027）

从自定义组件迁移至 shadcn/ui + Radix UI 的核心原因：

1. 一致性：所有组件共享同一设计 Token 体系

2. 可维护性：Radix UI 提供无样式但功能完善的原始组件

3. 无障碍：Radix 内置 ARIA 支持，通过 ARIA 合规测试套件

4. 生态兼容：Tailwind CSS 4.x 原生支持，与项目技术栈无缝集成

5. TypeScript 安全：严格的类型定义，消除 as any 强制转换
