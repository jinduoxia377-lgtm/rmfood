# DS Bot v3.2 方案深度自审报告（专家核查）

> 核查对象：`docs/DSBot任务驱动自动建群设计方案.md`（v3.2：MCP 客户端集成 + 任务中心）
> 方法：架构师视角的"落地会崩点"审计，针对代码现状逐项验证
> 结论：方案方向正确，但存在 **6 项 P0 严重问题**（不解决会导致 MCP 不可用 / 任务卡死 / 成本失控 / 数据不一致）和 **4 项 P1 问题**。

---

## 一、MCP 集成相关的严重问题（P0）

### M1. MCP 工具动态注册与 orchestrator「静态注册表」冲突（结构性）
- **现状**：orchestrator 工具注册表 `services/ai/agent/tools/__init__.py` 的 `_registry` 是**模块级静态单例**，工具在模块导入时注册；`execute_smart` 每次执行时 `self._registry.list_tools()` 取一次 schema。
- **方案缺陷**：v3.2 说"系统启动时从启用的 MCP 服务器拉取工具并注册"，但未解决：
  - 服务器工具变更/下线时 schema 缓存如何刷新；
  - 服务器不可用时已注册工具是保留（调用失败）还是移除；
  - `BotManager.validate_capabilities` 校验 `mcp:<server>` 时注册表里还没有工具 → 被忽略。
- **必须修订**：MCP 工具采用「**懒加载 + 全局缓存（按 server，短 TTL）+ 每次执行前按 Bot 绑定的服务器增量注册**」；`validate_capabilities` 对 `mcp:` 前缀放行而非校验注册表。

### M2. MCP 工具在 Bot 执行过程中才注册，导致本次执行不包含
- `execute_smart` 在循环开始前确定 `tools_schema`；若 MCP 工具在循环中途才注册，**本次执行的 LLM 看不到这些工具**。
- **必须修订**：在 `execute_smart` 构造 `tools_schema` 之前，先根据 `allowed_tools` 中的 `mcp:<server>` 标记**同步拉取并注册**对应服务器工具；并缓存避免每次连接。

### M3. MCP 传输实现成本与可靠性未明确（范围风险）
- Python `mcp` SDK 依赖较重；`stdio` 传输（子进程）在 Windows + uvicorn 后台任务场景不可靠；项目后端尚无 MCP 客户端依赖。
- **必须修订**：明确**首个落地只支持 HTTP/SSE 远程 MCP 服务器**（JSON-RPC over HTTP 可自实现，无重型依赖），`stdio` 列为 P2 可选；并在依赖清单中锁定版本。

### M4. MCP 安全边界不够细
- 方案仅有"管理员配置 + 白名单 + 审计 + 输出校验"，但缺：
  - **参数级注入校验**（外部工具参数可能被 LLM 构造出危险操作）；
  - **租户/用户级授权**（普通用户触发的任务能否使用管理员配置的 MCP 服务器？）；
  - **服务器凭据隔离**。
- **必须修订**：`ai_mcp_servers` 增加 `tenant_id` 与 `visibility`（org/private）；调用前做工具级与参数级检查；输出过 `check_output`。

### M5. MCP × delegate 嵌套调用延迟叠加
- delegate 创建的目标 Bot 也要暴露 MCP 工具 → 每次子任务都要连接 MCP 服务器拉 schema → 延迟与失败概率叠加（已有 LLM 串行 2-5 分钟，再加 MCP 网络往返）。
- **必须修订**：MCP 工具 schema **全局进程内缓存**（TTL 60s），连接失败降级（工具标记不可用并在结果中说明）。

## 二、任务中心/任务状态相关问题（P0）

### M6. 任务状态"完成判定"不可靠（会卡死）
- 方案：后台派单写【汇总】时把任务置为 `completed`。
- **缺陷**：
  - 派单失败（Chief 异常/LLM 全挂）→ 没有【汇总】→ 任务**永远卡在"派单中"**；
  - task_id 如何传递到 `_run_autodispatch_in_new_session` 未定义（需要 context 携带 task_id 并在完成回调更新）；
- **必须修订**：
  - 任务表增加 `status in (recruiting, dispatching, completed, failed, archived)`；
  - `_run_chief_dispatch` 的 try/except 中**同时更新任务状态**（成功→completed，异常→failed）；
  - 增加**超时任务扫描**（创建后 N 分钟仍非 completed → 标记 failed/timeout）。

### M7. 任务创建无限流（成本爆炸）
- `auto-team` 每次都会**建群 + 配人 + 派单**（10~24 次 LLM），比普通发言派单成本更高。
- 方案只复用了发言级限流（未覆盖 auto-team）。
- **必须修订**：`POST /tasks/auto-team` 单独限流（同用户每 5 分钟 1 次，或按套餐配额）；前端按钮防重复提交。

### M8. 建群与建任务记录缺少事务一致性
- 创建任务 = 插入 `ai_task_groups` + 创建 `ai_bot_group_sessions` + 写入初始消息。任一步失败都会造成"有群无任务"或"有任务无群"。
- **必须修订**：`create_task_team` 在同一数据库事务中完成建群+建任务+写消息（同一 session，失败整体回滚；后台派单另起会话）。

## 三、角色/配人相关问题（P1）

### M9. MCP 能力未纳入角色评分
- 角色模板的 `required_tools` 是内置工具名；而 AI 员工的能力含 `mcp:<server>` 标记。
- 评分公式的"工具覆盖率"无法计算 MCP 服务器匹配 → L1 匹配可能错误地把"有 MCP 文献服务器"的员工判为低分。
- **修订**：`RoleTemplate` 增加 `required_mcp_servers`；评分公式增加"外部能力匹配"维度（0.2 权重）。

### M10. 角色解析结果不可人工干预
- TaskPlanner 一次定人，若配错角色（LLM 判断偏差），用户**无法在派单前调整团队**。
- **修订**：任务创建后提供"派单前预览"（可选）：展示【任务分配】与成员，用户可确认或追加专家后手动触发派单；默认仍自动派单（高级选项）。

---

## 四、前端/数据一致性（P1）

### M11. 任务中心与群聊协作双入口的状态一致性
- 同一群聊在"任务中心执行视图"和"群聊协作"都用 `GroupChatView` 展示，消息轮询/状态各自维护，可能出现状态不同步。
- **修订**：任务中心执行视图复用**同一个** `GroupChatPanel/GroupChatView` 组件与状态管理；任务状态以 `ai_task_groups.status` 为权威，群聊消息仅作展示。

### M12. MCP 服务器管理前端缺失
- 方案只说了后端配置，没有管理 UI（系统设置里配置 MCP 服务器列表/启用/测试连接）。
- **修订**：新增"系统设置 → MCP 服务器"管理页（列表/新增/测试连接/启停/工具白名单）。

## 五、必须修订清单（P0/P1 汇总）

| 编号 | 问题 | 级别 | 修订要点 |
|:---|:---|:---|:---|
| M1 | MCP 动态注册 vs 静态注册表 | P0 | 懒加载 + 全局缓存 + 执行前按 Bot 绑定增量注册；`mcp:` 放行校验 |
| M2 | MCP 工具中途注册本次不可见 | P0 | 构造 tools_schema 前同步注册 |
| M3 | MCP 传输成本未明确 | P0 | 首版只支持 HTTP/SSE 远程服务器，stdio 列为 P2 |
| M4 | MCP 安全边界 | P0 | 租户/可见性/参数校验/输出校验 |
| M5 | MCP×delegate 延迟 | P1 | schema 进程内缓存 TTL 60s + 连接失败降级 |
| M6 | 任务完成判定会卡死 | P0 | 状态含 failed + 完成回调更新任务 + 超时扫描 |
| M7 | auto-team 无限流 | P0 | 单独限流（5 分钟 1 次）+ 前端防重复 |
| M8 | 建群/建任务无事务 | P0 | 同一事务建群+任务+初始消息 |
| M9 | MCP 未纳入角色评分 | P1 | RoleTemplate 加 required_mcp_servers + 评分权重 |
| M10 | 角色解析不可干预 | P1 | 派单前预览（可选）/ 追加专家 |
| M11 | 双入口状态不一致 | P1 | 复用同一组件，任务状态权威 |
| M12 | MCP 管理前端缺失 | P1 | 系统设置 MCP 管理页 |

## 六、结论

v3.2 在方向上是正确的，但 **MCP 集成与任务状态机是"实施前必须补齐的 P0 硬伤"**：若不解决 M1/M2，MCP 工具实际不会出现在 Bot 的 function-calling 中；若不解决 M6/M7/M8，任务中心会卡死、成本失控、数据不一致。建议先按上表修订为 v3.3，再进入开发。
