# RMFOOD 后端服务维护指南

## 1. 系统架构

RMFOOD 后端服务基于 FastAPI 框架构建，主要组件包括：

- **FastAPI**：Web 框架
- **SQLite**：默认数据库
- **Redis**：可选缓存服务
- **WebSocket**：实时通信
- **监控系统**：健康检查和错误预警

## 2. 服务管理

### 2.1 启动服务

使用提供的启动脚本启动服务：

```bash
# Windows
.tart.bat

# Linux/Mac (需要转换为 shell 脚本)
chmod +x start.sh
./start.sh
```

服务将在 `http://localhost:8000` 上运行。

### 2.2 停止服务

使用提供的停止脚本停止服务：

```bash
# Windows
.top.bat

# Linux/Mac (需要转换为 shell 脚本)
chmod +x stop.sh
./stop.sh
```

### 2.3 查看服务状态

- **健康检查**：`http://localhost:8000/health`
- **API 文档**：`http://localhost:8000/docs`
- **指标监控**：`http://localhost:8000/metrics`

## 3. 监控系统

### 3.1 健康检查

健康检查端点提供以下信息：

- 服务状态（healthy/degraded）
- 运行时间
- 请求统计
- 错误统计
- 响应时间
- 系统资源使用情况
- 各服务组件状态

### 3.2 错误预警

错误预警系统会在以下情况触发预警：

- 每分钟错误数超过阈值（默认 10 个）
- 系统会记录错误类型和上下文
- 预警信息会记录到日志中

### 3.3 日志管理

日志文件位于 `logs` 目录：

- `rmfood.log`：所有日志
- `rmfood_error.log`：错误日志

建议定期清理或归档日志文件，避免占用过多磁盘空间。

## 4. 常见问题处理

### 4.1 服务无法启动

- 检查端口是否被占用
- 检查依赖是否正确安装
- 检查数据库连接
- 查看日志文件了解具体错误

### 4.2 服务响应缓慢

- 检查系统资源使用情况
- 检查数据库性能
- 检查是否有长时间运行的任务
- 考虑增加服务器资源

### 4.3 数据库连接问题

- 检查数据库文件权限
- 检查数据库连接字符串
- 考虑使用更强大的数据库（如 PostgreSQL）

### 4.4 内存占用过高

- 检查是否有内存泄漏
- 优化代码中的内存使用
- 考虑增加服务器内存

## 5. 性能优化

### 5.1 代码优化

- 使用异步编程
- 优化数据库查询
- 使用缓存减少重复计算
- 合理使用索引

### 5.2 配置优化

- 根据服务器资源调整 uvicorn 工作进程数
- 配置合适的超时设置
- 优化数据库连接池

### 5.3 部署优化

- 使用进程管理器（如 PM2、Supervisor）
- 配置负载均衡
- 考虑使用容器化部署

## 6. 安全措施

### 6.1 生产环境配置

- 修改 `SECRET_KEY` 为强随机字符串
- 禁用调试模式
- 配置 HTTPS
- 限制 CORS  origins

### 6.2 定期维护

- 备份数据库
- 更新依赖包
- 检查安全漏洞
- 监控异常访问

## 7. 监控指标

### 7.1 关键指标

- **请求量**：每分钟请求数
- **错误率**：错误请求占比
- **响应时间**：平均和最大响应时间
- **系统资源**：CPU、内存、磁盘使用率
- **数据库性能**：查询响应时间

### 7.2 监控工具

- 可集成 Prometheus + Grafana 进行更详细的监控
- 可使用 ELK 栈进行日志分析

## 8. 备份策略

### 8.1 数据库备份

建议定期备份 `rmfood.db` 文件：

```bash
# 手动备份
copy rmfood.db rmfood_backup_$(date +%Y%m%d).db

# 自动备份脚本
# 可创建定时任务执行备份
```

### 8.2 配置文件备份

- 备份 `.env` 文件
- 备份 `pyproject.toml` 和 `requirements.txt`

## 9. 升级步骤

### 9.1 代码升级

1. 停止服务
2. 备份关键文件
3. 更新代码
4. 安装新依赖
5. 启动服务
6. 验证服务正常运行

### 9.2 数据库迁移

- 对于数据库结构变更，需要编写迁移脚本
- 测试环境验证后再应用到生产环境

## 10. 紧急响应

### 10.1 服务崩溃

1. 查看日志文件了解崩溃原因
2. 尝试重启服务
3. 如果问题持续，检查系统资源和配置
4. 必要时回滚到之前的稳定版本

### 10.2 安全事件

1. 立即停止服务
2. 备份相关日志
3. 分析事件原因
4. 修复安全漏洞
5. 增强安全措施
6. 重新启动服务

## 12. 附录

### 12.1 环境变量配置

参考 `.env.example` 文件配置环境变量：

```
# 应用配置
APP_NAME=RMFOOD配方设计平台
APP_VERSION=1.0.0
DEBUG=false

# 数据库配置
DATABASE_URL=sqlite+aiosqlite:///./rmfood.db

# 安全配置
SECRET_KEY=your-secret-key-here

# CORS配置
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000

# 其他配置...
```

### 12.2 依赖管理

使用 `requirements.txt` 管理依赖：

```bash
# 安装依赖
pip install -r requirements.txt

# 更新依赖
pip freeze > requirements.txt
```

### 12.3 开发建议

- 使用虚拟环境隔离依赖
- 编写单元测试和集成测试
- 使用版本控制系统管理代码
- 遵循 PEP 8 代码规范
