## 一、权威基准判定（先于一切改动）

### 1.1 桌面端「已落地」主题 ≠ DESIGN.md 规范色

经核查，存在**规范与实现分叉**：

| 来源 | 品牌主色 | 说明 |
|:-----|:---------|:-----|
| `DESIGN.md §2.1` | `#0066CC`（蓝） | 规范文档写的是 Apple Action Blue |
| 桌面 Web 运行时（已落地） | `#047857`（绿） | `base.css:28 --color-primary: var(--color-primary-surface, #047857)`；`-500: #10b981`；暗色 `#34d399` |
| `theme.presets.ts` | `#10b981`（绿） | 注释明确「= base.css 的 --color-primary（规范 §13 权威）」 |

**结论**：桌面 Web 实际运行的是**绿色**主色，DESIGN.md §2.1 的蓝色是未被桌面实现采纳的规范值。小程序当前跟随了规范的蓝色，反而与桌面实际不一致。

### 1.2 本方案采用的基准

按任务要求「以桌面端**已正式落地**的主题系统规范为统一基准」，本方案以桌面 Web 运行时 L0 令牌为**唯一权威**：

| 语义 | 桌面亮色 | 桌面暗色 |
|:-----|:---------|:---------|
| `--color-primary`（主色/实底） | `#047857` | `#34d399` |
| `--color-primary-500`（主色强调） | `#10b981` | `#34d399` |
| `--color-secondary` | `#1d4ed8` | `--color-secondary-600` |
| `--color-accent` | `#6d28d9` | `--color-accent-600` |
| `--color-success` | `#047857` | 暗色 success |
| `--color-warning` | `#b45309` | 暗色 warning |
| `--color-error` | `#b91c1c` | 暗色 error |
| 页面背景 `--bg-canvas` | `neutral-50 #f8fafc` | `neutral-950` |
| 正文文字 | `#111827` 系（Web 实际） | `#f3f4f6` 系 |

> ⚠️ **决策点（需产品确认，默认按方案 A 执行）**
> - **方案 A（推荐）**：小程序品牌色对齐桌面绿色系。改动集中在 `design-tokens.wxss` 的品牌令牌 + `theme.json`/`app.json` 的 TabBar 选中色，Icon 由 token_colors.js 重新生成后自动跟随。
> - **方案 B**：保持蓝色作为全端品牌，需把桌面 Web 全站主色改为蓝（影响 100+ 组件与对比度裁决，成本极高），不推荐。
> - 无论选哪个，都需**同步修订 DESIGN.md §2.1**，消除规范与实现的长期分叉。

## 三、令牌层对齐方案（核心）

### 3.1 小程序令牌 → 桌面 L0 映射表

在 `design-tokens.wxss` 中建立/调整以下映射（`page { ... }` 内）：

```css
/* ===== 品牌色（方案 A：对齐桌面绿） ===== */
--color-brand-primary: #047857;   /* 桌面 --color-primary（亮） */
--color-brand-primary-active: #059669;  /* 桌面 -600 */
--color-brand-primary-emphasis: #10b981; /* 桌面 -500 */
--color-brand-primary-weak: #d1fae5;    /* 桌面 -100（容器底） */
--color-brand-primary-dark: #34d399;    /* 桌面暗色 -500 */

/* 深色模式覆盖（dark-mode.wxss） */
/* --color-brand-primary: #34d399;  --color-brand-primary-weak: rgba(52,211,153,0.15); */

/* ===== 主色别名 ===== */
--color-primary: var(--color-brand-primary);          /* 亮 = #047857 / 暗 = #34d399 */
--color-primary-light: rgba(16, 185, 129, 0.12);      /* 跟随 -500 */
```

> 若产品确认方案 B（保持蓝），则跳过 3.1 品牌段，仅修正 `--color-brand-500` 导航绿与 TabBar 的冲突。

### 3.2 重建 `scripts/gen-token-colors.js`（P0-2/P0-1 修复）

**目标**：从 `design-tokens.wxss` + `dark-mode.wxss` 解析全部 `--color-*` 令牌，生成 `utils/token_colors.js` 的 `LIGHT`/`DARK` 两表，并作为 build 步骤写入 `package.json`。

**生成器要点**：
1. 读 `design-tokens.wxss`（亮色表）与 `dark-mode.wxss`（暗色表）
2. 正则提取 `--color-([a-z0-9-]+):\s*([^;]+);`
3. 忽略 `var(...)` 别名（用其最终值展开，需一层解析）
4. 输出 `token_colors.js`（保留注释头，声明自动生成）
5. **自校验**：生成的表中所有颜色与 wxss 定义一致；并跑一遍 `mobile-audit.cjs` 确认 Icon 相关 token 无 GitHub 旧值残留

**完成后**：`<icon color="var(--color-bg-card)">` 在深色模式烘焙 `#2C2C2E`（而非 `#161B22`），与页面一致。

## 十、风险与回退

- **风险 1**：`token_colors.js` 重新生成后，部分 Icon 颜色变化（从 GitHub 深色 → Apple HIG），需截图回归确认非预期色变。
- **风险 2**：品牌色改绿后，`icon-showcase` 色板、分享图、渐变头像等视觉需同步核对。
- **回退**：`design-tokens.wxss` + `token_colors.js` 是单文件可回退点；字号/色令牌化分批提交，每批独立可回退。
